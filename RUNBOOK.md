# Spellgunners — ранбук

## Запуск

```bash
cd ~/projects/fast-game
.venv/bin/python main.py
```

Если установлен uv: `uv run main.py`.

Игра открывается на весь экран. F11 переключает окно / полный экран, F5 перечитывает картинки с диска. Закрыть игру — кнопка «Выход» внизу слева в главном меню (Esc там игру не закрывает).

**Пауза.** Esc (Options) в партии — пауза: «Продолжить», «Настройки», «Выйти». За одним компьютером и в разминке матч на паузе стоит; по сети партия идёт дальше, твой маг стоит. Из «Настроек» с паузы Esc возвращает в партию. Повторный Esc — продолжить.

## Первая установка (на новой машине)

Нужен только если папки `.venv` нет.

```bash
cd ~/projects/fast-game
python3 -m venv .venv
.venv/bin/pip install pygame pytest pyflakes
```

pytest и pyflakes нужны только для проверок (см. ниже), для игры хватает pygame.

## Установка на другие компьютеры (готовые сборки)

Готовая сборка — один файл, внутри всё: Python, pygame, картинки, звуки, шрифты. Ставить заранее ничего не нужно. Сборки лежат на странице выпуска на GitHub (Releases), как они туда попадают — в «Выпуск версии».

**Windows** — скачать `spellgunners-setup.exe` и запустить:

- Windows покажет «Система Windows защитила ваш компьютер» (SmartScreen: сборка не подписана платным сертификатом) → «Подробнее» → «Выполнить в любом случае».
- Установщик спросит про ярлык на рабочем столе; права администратора не нужны. Игра появится в «Пуск» как «Spellgunners», удалить — «Параметры» → «Приложения».
- При первой сетевой игре брандмауэр спросит разрешение — разрешить для **частных** сетей.
- Без установки: `spellgunners-windows.exe` — тот же файл игры, просто запустить.
- Настройки — в `%APPDATA%\duel`, при обновлении сохраняются.

**Linux** — скачать `spellgunners-linux.tar.gz`, в терминале:

```bash
tar xf spellgunners-linux.tar.gz
sh spellgunners/install.sh              # в меню приложений и ~/.local/bin/spellgunners, без sudo
sh spellgunners/install.sh --uninstall  # удалить (настройки в ~/.config/duel остаются)
```

Можно и без установки: `./spellgunners/spellgunners-linux`. Обновление — то же самое с новым архивом.

Проверить сборку без окна: `spellgunners-linux --selftest` (или `spellgunners-windows.exe --selftest`) — проиграет несколько секунд и сетевую игру с ботом, код выхода 0 — всё в порядке.

## Обновление игры

Игра при запуске в фоне спрашивает GitHub о последней версии. Если есть новее — в меню пункт **«Обновить до X»**: скачивает файл, проверяет контрольную сумму, ставит.

- **Linux**: заменяет `~/.local/bin/spellgunners` (куда ставит `install.sh`) и перезапускается.
- **Windows**: тихо запускает установщик выпуска, игра закрывается; установщик ставит новую версию и сам её открывает.
- Своя версия и время последней проверки — в правом нижнем углу меню («v0.6.0 · проверено 14:32»); щелчок по ним — проверить сейчас. То же — Настройки → **«Проверить обновления»** (с итогом: «у вас последняя версия», «есть версия X», «нет связи с GitHub»). Сборка выпуска на GitHub идёт 5–10 минут: если игру открыли раньше, проверьте ещё раз.
- Нет интернета — игра просто работает дальше. Проверку можно выключить: Настройки → «Проверять обновления».
- Запуск из исходников (`python main.py`) только пишет «Есть версия X — обновить: git pull».
- Версии до 0.5.0 автообновления не знают: первый раз поставить вручную, дальше — кнопкой.
- **Windows:** установщик ждёт, пока игра закроется (до 20 с), потом ставит и запускает новую версию. Журнал тихой установки — `%TEMP%\spellgunners-update.log`: если обновление не встало, причина там. Старые версии (до 0.7.2) метку не берут — тогда установщик просто ждёт 4 с. Если всё же откатилось — закройте игру и запустите `spellgunners-setup.exe` со страницы релиза вручную.
- **Одна копия.** Игра запускается в одной копии: вторая сообщает «Spellgunners уже запущен» и закрывается. Для проверки сети на одном компьютере — `DUEL_MULTI=1 python main.py ...`.
- Если подключение не удалось из-за «другой версии игры», а обновление есть — об этом скажет ошибка.

Как устроено: `duel/update.py` (запрос `api.github.com/repos/…/releases/latest`, репозиторий — `UPDATE_REPO` в `duel/config.py`); сборка вшивает версию в `duel/_version.py`; выпуск получает `SHA256SUMS` — без него и при несовпадении игра ничего не ставит.

## Выпуск версии (GitHub)

Один раз — создать на GitHub пустой репозиторий с любым именем (например, `vibegame`; без README и .gitignore) и отправить туда код:

```bash
git remote add origin git@github.com:ИМЯ/РЕПОЗИТОРИЙ.git
git push -u origin master
```

Выпуск — метка версии (номер поднять и в `pyproject.toml`):

```bash
git tag v0.2.0
git push origin v0.2.0
```

GitHub сам (`.github/workflows/release.yml`, 10–15 минут) сначала прогонит «Проверки» (`ci.yml`: тесты и самопроверка на Linux и Windows, спецификации OpenSpec) и сверит метку с версией в `pyproject.toml` — сборка начнётся, только если всё зелёное; потом соберёт Linux и Windows, проверит обе сборки `--selftest` и выложит на страницу выпуска `v0.2.0`: `spellgunners-setup.exe`, `spellgunners-windows.exe`, `spellgunners-linux.tar.gz`, `spellgunners-linux`, `install.sh`. Ход сборки — вкладка Actions. Собрать без выпуска — Actions → «Сборка и выпуск» → Run workflow (файлы — в результатах запуска).

**Проверки на каждый push** (`.github/workflows/ci.yml`, вкладка Actions → «Проверки»): pyflakes, тесты и `--selftest` из исходников на Linux и Windows, спецификации OpenSpec. Красный значок у коммита — что-то сломалось ещё до выпуска. Падение на любой из систем — красная проверка. Подробности упавших тестов видны в аннотациях запуска (Actions → запуск → Annotations).

**Собрать на этом ноутбуке** (только Linux; Windows-сборку собирает GitHub):

```bash
.venv/bin/pip install pyinstaller pillow     # один раз
.venv/bin/python tools/build.py              # dist/spellgunners-linux, install.sh, spellgunners-linux.tar.gz
dist/spellgunners-linux --selftest
```


**Если в выпуске менялись настройки сервера** (`deploy/`: Caddyfile, службы, таймеры — кроме `autoupdate.sh` и `site.sh`): сервер обновит код сам, а настройки — только после `cd /opt/spellgunners && sudo bash deploy/install.sh spellgunners.duckdns.org` на сервере. Записать выпуск в таблицу «Выпуски, которым нужен шаг на сервере» в `docs/deploy-aws.md`.

## Браузерная версия (проба, pygbag)

**Играть без установки:** https://spellgunners.duckdns.org/ — сайт сервера: «Play in the browser», скачать для Windows и Linux, кто онлайн. Каждый выпуск GitHub собирает браузерную версию (`spellgunners-web.zip` в выпуске, задача `web` в `.github/workflows/release.yml`), а сервер при переходе на выпуск кладёт её себе в `/play/` (`deploy/site.sh`). Первая загрузка ~минута; по сети — к этому же серверу.

Тот же код игры, собранный в WebAssembly (pygbag); основная — компьютерная, браузер — «попробовать». Отличия только при `duel/platform.py: WEB`: в браузере нет игры по сети (нужен сервер с WebSocket и TLS — следующий шаг), своего сервера и автообновления; звуки — `.ogg` (сборщик переводит через ffmpeg).

```bash
.venv/bin/pip install pygbag                     # один раз (группа web в pyproject.toml)
.venv/bin/python tools/build_web.py              # build/web-src: web/main.py + duel/ + assets/
.venv/bin/python -m pygbag build/web-src         # http://localhost:8000 — первая загрузка ~минута
# порт 8000 занят? тестовый сервер pygbag работает только на нём — тогда так:
.venv/bin/python -m pygbag --build build/web-src
python3 -m http.server 8123 --bind 127.0.0.1 -d build/web-src/build/web   # http://127.0.0.1:8123/
DUEL_WEB=1 .venv/bin/python build/web-src/main.py   # то же без браузера: ветки «как в браузере» на компьютере
```

**По сети из браузера.** Браузер ходит только по WebSocket: сервер слушает его на порту 5560 (`python -m duel.server --ws-port 5560`, по умолчанию так и есть; TCP 5555 для компьютеров — как раньше). В браузере «Подключиться к серверу» — адрес `ws://host:5560/` (на своём компьютере) или `wss://имя.домен/` (сервер в интернете за Caddy или Cloudflare Tunnel — со страницы https можно только wss). Адрес по умолчанию — `WEB_SERVER` в `duel/config.py`. Компьютерная игра тоже понимает `ws://` и `wss://` в строке адреса. Переподключения после обрыва в браузере пока нет — обрыв возвращает в меню.

Ошибки браузерной версии — в консоли браузера (F12) и в терминале pygbag на странице (адрес с `#debug`). В браузере нет геймпадов (pygame-ce в WebAssembly без `pygame._sdl2.controller`).

## Поле

Левая половина поля — земля левого игрока, правая — правого (вид земли — по герою). В центре — круглая **арена мобов**, над и под ней — **нейтральная полоса** (серый камень). На **чужой земле** жжёт (2 жизни/с) и идёшь медленнее (×0,6); на нейтральной полосе — не жжёт и скорость обычная; в **арену** заходить можно — медленнее (×0,6), не жжёт, но там стражи. Стартовые позиции — у левого и правого края. На поле пять построек-магазинов: две боковые на землях игроков, две в нейтральной полосе и одна в центре арены. Это объекты игрового поля — на них можно встать; пока герой стоит на магазине, в верхнем углу его экрана открывается панель покупок. Все фигуры (маги, мобы, стражи, пули, артефакты) — в масштабе `UNIT_SCALE` = 0,75. Числа — `FOE_LAND_DPS`, `FOE_LAND_SLOW`, `ARENA_SLOW`, `NEUTRAL_HALF`, `FIELD_LEFT`, `FIELD_RIGHT`, `SHOP_WIDTH`, `SHOP_ROW_H`, `SHOP_PAD` в `duel/config.py`.

**Стражи арены** — четыре: два слева охраняют арену от левого игрока (дальнобойный сверху, ближний снизу), два справа — от правого. Пока «их» игрок вне арены, стражи — серые статуи: неуязвимы, пули отскакивают. Вошёл в арену — его стражи просыпаются (кольцо цвета героя): ближний идёт и бьёт, дальнобойный стреляет. Ранить стража можно только из арены (пулей, лучом, ударом); 10 жизней; убитый оставляет деньги и возвращается через 60 с (`GUARDIAN_*`).

Статус (верхняя полоса): у края — имя и жизни, под ними запас денег (монета), патроны и всё, что действует, с таймерами; ближе к центру — ячейки инвентаря и очередь; в самом центре — таймер волн мобов.

## Меню

**Мышью** — во всех меню: наведение выбирает, левая кнопка нажимает, правая — назад (кроме главного меню и партии). Внизу главного меню — «Выход», на экранах — «←», в лобби сервера — «Ищу соперника / Играть с ботом / Разминка», на выборе героя — карточки героев и «Готов / Выйти».

Перед каждой партией — отсчёт **3 – 2 – 1 – «В бой!»** (за одним компьютером, по сети, на реванше и в разминке): поле видно, но всё стоит. Длина — `COUNTDOWN` в `duel/config.py` (0 — без отсчёта).


| Пункт | Что это |
|---|---|
| 1. Два игрока | двое за одним компьютером: сначала выбор героев, потом партия (левый против правого) |
| 2. Играть по сети | серверы в сети, свой сервер, адрес вручную → лобби сервера (игроки, партии, вызов, поиск, бот) → партия (см. «Игра по сети») |
| 3. Тест с ботом | обычная партия против бота (жизней как обычно; больше — `/hp 1000` в консоли), с выбором героев |
| 4. Обучение | об игре (ролик), маги, артефакты по землям, правила |
| 5. Настройки | язык, имя, прицел, проверка обновлений |
| 6. Обновить до X | появляется, когда вышла новая версия (см. «Обновление игры») |

Игра — для двух живых игроков: за одним компьютером режима против компьютера нет. Бот бывает только в сетевой игре — на месте второго игрока.

**Бот** — на правилах (`duel/brain.py`), играет «по-человечески»: видит партию с задержкой реакции, уклоняется от летящих пуль, бьёт мобов и подбирает деньги, ходит в магазины (свой, нейтральные и чужой) и покупает нужные артефакты; своя земля важнее нейтральной, нейтральная — важнее чужой, снаряжение покупает до предела стека, уже имеющиеся артефакты не дублирует. Держит свою дистанцию и стреляет с упреждением и разбросом, бьёт мечом вблизи, уходит с опасной земли, применяет артефакты по простым правилам (лечение — при малых жизнях, очищение — под дебаффом, круг огня и зеркало — в соперника, ледяная тропа — только чтобы зайти на жгучую землю, заморозка — и для атаки: замороженного он подходит и бьёт). Играет как люди — агрессия: напирает (дистанция боя 210–270), бьёт мобов (и в арене — с края), за пачками идёт тем охотнее, чем меньше патронов; издалека по сопернику — не чаще раза в 0,8 с, без патронов уходит в середину своей земли (пачки падают туда). Пачки старается не пропускать (скоро пропадёт, а успевает — бежит), пачку на чужой земле у самой границы (до 70 px) ворует, если жизней хватает и соперника рядом нет; у соперника кончаются патроны, а рядом с ним пачка — иногда бьёт в эту точку. Земля надевает «Твёрдую почву», чтобы собрать деньги в арене мобов. Невидимку не видит. Сложность — «Настройки → Бот: лёгкий / обычный / сложный» (реакция 0,35 / 0,25 / 0,17 с, разброс прицела 14° / 8° / 4°); действует в «Тесте с ботом» и в разминке, на сервере бот — обычный. **ИИ-бот** (черновик, на паузе): обученные сети из `assets/ai/` (в git не идут) появляются в «Настройки → Бот: ИИ <имя>» — «Тест с ботом» и разминка играют против неё (реакция обычного бота, решения — сеть; сеть другой раскладки — играет бот на правилах). Учить — `tools/ai_train.py --name fire-v2 --hero fire --minutes 60` (нужны numpy и torch в `.venv`), проверять — `tools/ai_eval.py --name fire-v2 --hero fire --opponent hard --details`. Прогон партий бот против бота без экрана (заготовка лаборатории баланса): `.venv/bin/python tools/botmatch.py --games 100` (`--blue hard --red easy`, `--red random`, `--heroes fire,frost`) — победы по сторонам и героям, средняя длительность.

**Лаборатория баланса** — тысячи партий бот против бота без экрана (все ядра) и отчёт, где игра кривая. Из игры (только настольная) — аддон «Лаборатория»: «Настройки → Дополнительно → Аддоны…», включить, «Лаборатория…» — форма (режим, партий, уровень, стратегия, пара героев; в отчёте — свой бот на каждую сторону: любой уровень и стратегия или обученная сеть ИИ; подмена параметров, повторы), «Запустить» — в фоне (можно играть), прогресс, «Остановить»; отчёт — на экране и в `logs/lab-reports/<время>.txt`; «Смотреть повторы прогона». Из командной строки:

```bash
.venv/bin/python tools/lab.py report --games 600                  # стороны, длительность, герои и пары, камбэки, снежный ком, артефакты
.venv/bin/python tools/lab.py report --games 600 --level easy     # то же у слабых ботов
.venv/bin/python tools/lab.py strats --level all --games 40       # есть ли выигрышная стратегия на каждом уровне
.venv/bin/python tools/lab.py sweep GEAR_STACK=1,3,5 --games 300  # как параметр меняет игру
.venv/bin/python tools/lab.py knobs SPEED                         # какие параметры есть
.venv/bin/python tools/lab.py report --games 1800 --replays       # и повтор каждой партии — смотреть в игре
.venv/bin/python tools/lab.py report --games 300 --team 2v2      # 2×2: напарник — тот же бот, что ведущий
```

`--replays` (в любом режиме) кладёт повтор каждой партии прогона в новую папку `logs/lab-replays/<время>-<режим>-<уровень>` (или `--replays ПАПКА`), ничего не удаляя; партия — около 40 КБ, 1800 партий — около 80 МБ (лишние папки удалять руками). В игре: «Настройки → Дополнительно → Смотреть повторы», ←/→ — папка (повторы игры или прогоны, новые первыми), ↑/↓ и колесо — листать, Enter — смотреть. Список открывается сразу: рядом с повторами лежит оглавление `index.json`.

Любой режим принимает `--set ИМЯ=знач` (несколько раз; таблицы — `--set ITEM_LEVEL.landswap=3`): партии идут с другими числами, сама игра не меняется. «!» рядом с процентом — отклонение от 50 %, которое не объяснить случаем; без «!» при малом n — шум. Важно: «герой слабый» в лаборатории может значить «бот плохо им играет» — смотреть вместе со стратегиями и уровнями. Стратегии бота: hero (стиль героя), rush (давит сразу), kite (бой издалека), farm (сначала мобы), turtle (сидит у себя). Уровни отличаются реакцией, прицелом и «температурой»: слабый бот выбирает не лучшее дело с вероятностью по его оценке.

Выбор: W/S, ↑/↓ или крестовина. Начать: Enter, Пробел, ✕ на геймпаде или цифра 1–6.

### Герои

**Уровни артефактов** (точки под значком): 1–2 — обычные, 3–4 — тяжёлые; уровень теперь только вид и справка, на выпадение не влияет (магазин продаёт всё). Уровень 4 — медведь, огненный круг, смена земель, лассо; 3 — зомби, ледяная тропа, лесные стражи, стена деревьев, дубовая кора, двойники; 2 — очищение, «не стреляет», «без артефактов», заморозка, щит, «пули замирают», скорострельность, перевод стрелок, стена-зеркало, луч света; остальные — 1. Таблица — `ITEM_LEVEL` в `duel/config.py`.

**Артефакты героев** — доступны только в боковом магазине этого героя (справка, страницы 2–4); купить может любой, кто стоит на магазине, а применить — тот, кто купил:

**«Обучение».** Вкладки сверху: Об игре (ролик и галка «Показывать при старте»), Маги (ходьба, выстрел, удар мечом), Артефакты, Правила (A/D, ←/→ или щелчок). На «Артефактах» — квадратики земель: нейтральная, земля мобов (снаряжение), шесть земель героев; щелчок или Enter — артефакты этой земли (стрелки — выбор квадратика, за краем — соседняя вкладка). Внутри земли слева — список (W/S, ↑/↓ или наведение мышью), справа — выбранный: окно сценки, название, описание; A/D — соседняя земля, Esc — к квадратикам. «Подробнее» (Enter, ✕, щелчок по окну или по выбранной строке) — сценка во весь экран.

**Сценки в справке.** У артефакта может быть сценка — маленькая настоящая партия по сценарию из `assets/demos/<артефакт>.json`. Это та же сцена, что в роликах (движок — `duel/scene.py`, формат и API — в его начале), только идёт по кругу в окошке 2:1: кто где стоит (`setup`: маги, мобы, артефакты), какой кусок поля показать (`view`), что и когда делают маги (`script`: `{"t": 0.9, "do": "cast", "who": "blue", "item": "lasso"}` — `do` бывает `cast`, `move`, `walk_to`, `aim`, `fire`, `melee`, `appear`, `drop`… — всё из API сцены), через сколько секунд заново (`length`), замедление (`speed`: 0.5 — вдвое медленнее). Нет файла — крупный значок и «сценки пока нет». Правишь файл, жмёшь F5 в справке — сценка обновилась.

**Эффекты заклинаний.** Анимации заклинаний рисует пакет `duel/fx/` (`mage.py` — на маге, `spells.py` — заклинания на поле, `bullets.py` — пули), а их числа — цвета, толщины, времена фаз, волны, количество искр — лежат в `assets/effects/<эффект>.json`. Правишь файл, жмёшь F5 (в игре или в справке) — видно сразу. Первый — `lasso.json`: бросок петли, захват, горящая верёвка с волнами и искрами, горящая петля на жертве, затухание.

**Маг и его анимации.** Маг — текстовый файл `assets/sprites/mage.sprite`: палитра «буква → цвет» и кадры буквами 32×32 — `idle` (стоит), `walk1`–`walk4` (шаг), `shoot` (отдача), `melee_wind` / `melee_hit` (замах и удар). Все герои — один рисунок с заменой цветов, поэтому ходят одинаково. Правишь буквы → F5. Рисовать в пиксель-редакторе: `.venv/bin/python tools/sprite_text.py export mage --scale 8` (PNG в `sprite_png/`), дорисовал — `tools/sprite_text.py import mage walk1 sprite_png/mage_walk1.png` (цвета — только из палитры; новый цвет — допиши строку в `palette`). Меч со следом и вспышка выстрела — эффекты, их числа в `assets/effects/sword.json` и `shot.json`. При ударе мечом автомата в руках нет.

**Медведь, тройной выстрел, зомби.** Медведь — текстовый `assets/sprites/bear.sprite` (кадры `idle`, `run1`–`run4`, `swipe_wind` / `swipe`; правится так же, как маг; ошейник `k` перекрашивается в цвет героя). Первый черновик нарисовал `tools/make_bear.py` — повторный запуск затрёт ручные правки. Превращение мага в медведя (вспышка, клочья шерсти, рост) — числа в `assets/effects/bear.json` (там же размер медведя `scale` и скорость бега `run_fps`). Тройной выстрел — у автомата раскрываются ещё два ствола веером: `assets/effects/triple.json`; звук — `assets/sounds/3shoot-effect.mp3`. Превращение моба в зомби — руны цвета Тьмы, зелёный туман, моб корчится и зеленеет: `assets/effects/zombie.json`; зомби — спрайт моба в трупных цветах (`MOB_ZOMBIE_PALETTE` в `config.py`); пока идёт превращение (`ZOMBIE_RISE` = 0,9 с), зомби стоит и не бьёт. Сценки в справке: `bear`, `triple`, `zombies`.

**Луч, ледяная тропа, заморозка.** Каст «Луча света» (нимб, звезда у руки, кольца, искры; сам луч мерцает) — `assets/effects/beam.json`; свет рисуется сложением цветов, поэтому светится. «Ледяная тропа» (шипы при касте, льдинки с трещинами, снежинки у ног) и заморозка (лёд нарастает, глыба, раскол на осколки) — общий `assets/effects/ice.json`. Сценки: `beam`, `icewalk`, `foe_freeze`.

**Пули, попадания, горение.** Пули — в стихии героя (огненный шар, ледяной осколок, лист, сгусток тьмы, звезда), попадание — короткая вспышка в той же стихии (у моба — брызги слизи, у мага — звёздочки, у щита — рябь), маг на чужой земле горит стихией хозяина земли (огонь, мороз, яд, тьма, святой свет). Рисует `duel/fx/bullets.py`, цвета и размеры — `assets/effects/bullets.json` (F5). В справке на вкладке «Маги» — «Чужая земля» со сценкой `foe_land`.

**Полоска жизней, щит, терновник.** Над магом и мобом — сплошная полоска (без делений), заполнена по доле жизней, число жизней — внутри неё; голубой кусок справа — заряды щита: щит гасит любой урон, и чужой земли тоже, — и тают сначала они. Числа — `assets/effects/hpbar.json`. Щит — пузырь с сотами, зарядами по ободу, рябью от ударов и осколками (`shield.json`). «Стена деревьев» — терновник (`thorns.json`). Лечение и очищение — свои анимации (`heal.json`, `cleanse.json`) и звуки. Большие заклинания (огненный круг, медведь, зомби, смена земель, стена деревьев, толчки, лесные стражи, луч света) трясут поле на полсекунды — панель сверху не трясётся; сила и время — `EPIC_SHAKE` в `config.py`. Сценки справки идут на нейтральной полосе (вид `[340, 90, 320, 160]`, кроме «Чужой земли»), в них никто не погибает.

**Двойники, зеркало, огненный круг, луч.** «Луч света» бьёт на 4 жизни каждого, кого коснулся (один раз за луч; щит гасит его одним зарядом). «Двойники» появляются кучкой в магическом шуме там, где маг, и маг встаёт на случайное место в кучке — не уследить; двойники шагают и стреляют как маг; по сети хозяину свои двойники полупрозрачные (`clones.json`). Попадания рисуются на самой цели. Стена-зеркало — обсидиан с рунами и серебряное зеркало (`mirror.json`), огненный круг — рваное пламя, искры, дым (`firering.json`). Сценки: `clones`, `wall`, `firering`.

- **Свет**: «Луч света» — длинный (260 px) летящий луч насквозь, отскакивает от верха и низа, каждому — 4 урона и сбивает чужие пули и снаряды на пути; «убрать пули соперника»; «мир с мобами»; «невидимость» — 6 с по сети соперник (и зрители) мага не видят совсем, сам он видит себя полупрозрачным; за одним компьютером маг полупрозрачный, мобы теряют его из виду, зомби, лесные стражи и стражи арены не замечают (по арене можно прокрасться — стражи остаются статуями).
- **Холод**: «Ледяная тропа» — 8 с чужая земля не жжёт, за магом ледяной след (земля Холода, тает за 6 с); «заморозить соперника»; «щит»; «пули соперника замирают» — 5 с его пули висят в воздухе (касаться больно), потом летят дальше.
- **Природа**: «Стена деревьев» — 750 px по прицелу на 8 с, сквозь неё не пройти никому, кроме самой Природы; «Медведь» — 10 с большой медведь с 15 жизнями (в 1,3 раза быстрее мага), не стреляет, ближний удар дальше и сильнее; после — маг там, где превратился, с прежними жизнями; убили медведя — так же (маг жив). «Дубовая кора» — 6 с снимает дебаффы, и артефакты соперника на Природу не действуют (урон — действует); «Лесные стражи» — 3 дерева-стрелка на земле соперника на 10 с, бьют его в пределах 260 px, по 3 жизни.
- **Огонь**: «Огненное лассо» — 3 с тянет соперника, не вырваться; «Огненный круг» — кольцо 95 px вокруг ближайшего героя соперника (сам или двойник, не дальше `FIRE_RING_RANGE` = 380 px; никого — в случайное место рядом) на 6 с: стену не пересечь, у стены 4 жизни в секунду, пули изнутри гаснут; «быстрые пули»; «скорострельность».
- **Тьма**: «Восставшие мертвецы» — до 2 мобов рядом становятся зомби на 20 с, держатся не дальше 200 px от Тьмы и принимают её урон; «перевод стрелок»; «двойники» — не отличить от мага, бродят, по 2 жизни, подбирают артефакты хозяину; «стена-зеркало».

Числа — `BEAM_*`, `ICE_*`, `TREE_*`, `LASSO_SPEED`, `ZOMBIE_*`, `BEAR_*`, `FIRE_RING_*`, `CLONE_*`, `SENTRY_*`, `HERO_FADE` и `DURATION` в `duel/config.py`; что в каком магазине — `HERO_ONLY_ITEMS`, `GEAR_ITEMS`, `shop_items`.

Шесть героев: **Огонь** (красный, земля — лава), **Холод** (белый, лёд), **Природа** (зелёный, трава), **Тьма** (чёрный с фиолетовым, пепел), **Свет** (жёлтый, золотой камень), **Земля** (тёмно-зелёный, бурая почва с мхом). Скорость, жизни и выстрелы у всех одинаковые; у каждого — свои четыре артефакта (продаются только в его магазине, вкладка героя в справке). Цвет пуль, подписей и земли — по герою.

Экран выбора перед партией за одним компьютером: экран пополам — левый игрок слева, правый справа; у каждого сверху маленькие иконки магов, внизу — большая карточка выбранного (земля, маг, четыре заклинания); навести мышь на заклинание или вверх/вниз (свои клавиши, крестовина) — на карточке его сценка и описание; каждый листает своими клавишами «влево/вправо» и выбирает своим «выстрелом» или «ударом» (по умолчанию левый A/D и Space/E, правый ←/→ и Enter/R Shift; если клавиши переназначены в настройках — работают назначенные, подписи на экране показывают их). Мышь меняет выбор, только когда курсор правда сдвинулся; геймпады — крестовина и ✕, ○ — передумать; Esc — в меню. Одного героя вдвоём взять нельзя: на героя, которого уже выбрал соперник, можно встать, но выбрать — нет. Выбор запоминается до выхода из игры. В сетевом лобби герой меняется ←/→ (A/D, крестовина) на своей карточке; бот берёт случайного героя, его видно заранее — можно выбрать в ответ, в том числе его же (тогда бот берёт другого).

Как добавить героя: строка в `HEROES` и словарях `HERO_*` в `duel/config.py` (цвет, раскраска мага `MAGE_*_PALETTE`, фон), фон — в `tools/make_sprites.py`, название — `hero.*` в `duel/i18n.py`.
Из справки назад: Esc, Enter, Пробел, ✕ или ○.

Если жизней больше 5, в панели рисуется 5 сердечек и «+остаток»: например, `♥♥♥♥♥ +5` — это 10 жизней.

## Настройки и языки

Пункт меню «Настройки»:

- **Язык** — русский, English, suomi. При самом первом запуске (настроек ещё нет) игра сначала спрашивает язык — экран с тремя кнопками (подсвечен язык системы), потом ролик и меню; дальше язык меняется здесь. Выбор строки: W/S или ↑/↓, изменить: A/D, ←/→ или Enter (на геймпаде — крестовина и ✕), назад: Esc или ○. Меняется сразу.
- **Прицел стиком** (1–10, по умолчанию 6) — как быстро прицел поворачивается за правым стиком; 10 — сразу, 1 — медленно и точно. **Прицел мышью** (1–10, по умолчанию 5) — скорость перекрестия: 1 — в 5 раз медленнее мыши, 5 — как мышь, 10 — вдвое быстрее. Меняются A/D или ←/→.
- **Имя** — как тебя видят в сетевой игре (панель сверху, экран победы, список игр у других). Набирается на любом языке, до 16 символов; пока выбрана эта строка, буквы (и W/S) идут в имя, строки листаются стрелками ↑/↓, Backspace стирает. Пустое имя — «Синий»/«Красный», как раньше. За одним компьютером (хотсит) игроки всегда называются по цвету.

Всё запоминается между запусками в `~/.config/duel/settings.json` (Windows — `%APPDATA%\duel\settings.json`).

Логи — в папке `logs` рядом с настройками (`~/.config/duel/logs`, на Windows — `%APPDATA%\duel\logs`): `game.log` — запуски, партии, применённые артефакты, команды чата, вход и выход из сети; при падении — ещё `crash-<дата>.txt` с полным текстом ошибки (собранная игра на Windows показывает окно с путём к нему).

**Последние игры сервера.** В лобби сервера — кнопка «Последние игры» (или G): последние сетевые партии этого сервера (до 50: повторы в его `logs/replays/`), новые сверху — дата, режим, герои и имена, победитель, длительность; повторы другой версии помечены; вкладки «все» / «мои» (←/→). Enter или щелчок по выбранной — повтор, Esc — назад в список, ещё Esc — в лобби. Повтор приходит кусками по 48 КБ (`recent`, `recent_get` → `recent_part`). Работает и в браузере; свой сервер в игре показывает свои партии.

**Повтор партии.** Каждая законченная партия записывается в `logs/replays/<дата>-<режим>-<зерно>.json.gz` (последние 50; минута партии — около 10 КБ): начало партии и команды игроков по тактам, плюс тестовые команды. Сервер пишет повторы своих партий в свою папку логов, а при ошибке в комнате — ещё и повтор до ошибки.

Смотреть — **«Настройки → Дополнительно → Смотреть повторы»** (кроме браузера). Там же «Сохранять повторы: да/нет» и «Папка с повторами» (набрать путь, Ctrl+V — вставить; пусто — `logs/replays` рядом с настройками; под строками видно, куда пишутся сейчас). Список, новые сверху — дата, режим, герои, игроки или боты, кто победил, длительность, подменённые числа (⚙); Enter или щелчок — смотреть, Esc из повтора — обратно в список. Партии лаборатории баланса попадают туда же: `tools/lab.py report --games 1800 --json lab.jsonl`, потом `tools/lab.py replay lab.jsonl --pair земля,свет --winner right --count 3` (ещё `--pick N`, `--comeback`, `--longest`, `--shortest`; повторы — в ту же папку, что в настройках, или `--out`) — партия играется заново (всё детерминировано) и пишется повтором с режимом «лаборатория»; подменённые числа хранятся в повторе и при просмотре подменяются так же.

```bash
.venv/bin/python main.py --replay ~/.config/duel/logs/replays/….json.gz   # смотреть: пробел — пауза, ←/→ — скорость, ↑ — +10 с, R — сначала, Esc — выход
.venv/bin/python -m duel.replay ~/.config/duel/logs/replays/*.json.gz     # прогнать без окна и сверить итог с записанным
```

Партия повторяется точно, потому что матч не берёт случайность ниоткуда, кроме своего генератора с записанным зерном. Если `duel.replay` пишет «РАСХОЖДЕНИЕ» — значит, в правилах появилась неучтённая случайность (или повтор записан другой версией игры): это баг.

**Статистика баланса.** Итог каждой законченной партии — строкой JSON в `logs/matches.jsonl`: режим (`hotseat`, `test`, `warmup`; на сервере — `net`, `net-bot`, свой `matches.jsonl` рядом с `server.log`), герои, победитель, длительность, волна, жизни, снаряжение, что каждый подобрал и применил, выстрелы, полученный урон, зерно. Сводка:

```bash
.venv/bin/python tools/balance.py                        # партии за этим компьютером
.venv/bin/python tools/balance.py путь/к/matches.jsonl    # с сервера (можно несколько файлов)
.venv/bin/python tools/balance.py --all --since 2026-11-20   # с тестами и разминкой, с даты
```

Покажет процент побед героев и пар героев, какие артефакты подбирают и применяют и как часто побеждает применивший. Рядом с процентом — число партий: при 3–5 партиях проценты ничего не значат.

Все тексты игры — в `duel/i18n.py`, по словарю на язык. Новый текст добавляется во все три словаря с одинаковым ключом; тест проверяет, что ни один ключ не пропущен и числа (`{n}` и т. п.) везде одни и те же. Новый язык — ещё один словарь и строка в `LANGS`.

## Громкость и клавиши

В «Настройках»: **«Музыка: N»** и **«Звуки: N»** — от 0 (тишина) до 10, 5 — обычная; меняются сразу (звуки — с пробным звуком). При 0 не запускаются и шаги/циклы, уже звучащие — сразу замолкают. **«Клавиши…»** — экран назначения: левый и правый игрок за клавиатурой, действия (вверх, вниз, влево, вправо, выстрел, удар, ячейки 1–4) — выбрать, Enter (или щелчок), нажать новую клавишу; занятая меняется местами; Esc, F5, F11, P (пауза), T (чат) — служебные, их не назначить; «Сбросить по умолчанию». Подписи ячеек — по назначенным клавишам. Мышь и геймпад не переназначаются. Всё хранится в настройках (`music_volume`, `sfx_volume`, `keys`).

## Управление

| | Клавиатура и мышь (левый игрок) | Геймпад |
|---|---|---|
| Движение (в любую сторону) | W / A / S / D | левый стик или крестовина |
| **Прицел** (в любую сторону) | мышь | правый стик |
| Выстрел | левая кнопка мыши или Пробел | R1 или R2 |
| Ближний удар (только по мобам) | правая кнопка мыши или E | L1 или L2 |
| Артефакты, ячейки 1–4: первое нажатие — выбрать (видно только тебе: подсветка, куда пойдёт), второе — применить | 1 2 3 4 | □ △ ○ ✕ |
| Пауза | Esc | Options |
| После победы: ещё раз | R | ✕ |

**Режим прицела** (в «Настройках», строка «Прицел»): по умолчанию **«стик и мышь»** — всё, что ниже. **«По движению»**: прицел туда, куда идёт маг, стоит — прямо на соперника; стик и мышь не целятся (но кнопки мыши работают: левая — выстрел, правая — удар; по сети и в разминке — у своего мага), геймпад за одним компьютером не обязателен.

**Мышь в партии** двигает своё перекрестие на поле (системный курсор спрятан и не уходит из окна; в меню, лобби, на экране победы и при переключении окна — обычный курсор). **Правый стик** поворачивает прицел плавно; прицел меняется, только когда стик отклонён уверенно, — при отпускании не дёргается. Скорость того и другого — в «Настройках».

**Прицел** — это направление: пуля летит туда, куда смотрит стрелка рядом с магом, — хоть назад, хоть вверх, пока в кого-нибудь не попадёт: от всех четырёх стенок поля отскакивает, но не больше 3 раз — на четвёртой гаснет (`BULLET_WALL_BOUNCES`; стражи и зеркало не в счёт). Бег на направление выстрела не влияет. Маг поворачивается лицом к прицелу. Веер — три пули вокруг прицела.

**За одним компьютером нужен хотя бы один геймпад** (одному из двоих целиться нечем):

- **один геймпад** — левый игрок: клавиатура и мышь, правый: геймпад;
- **два геймпада** — первый у левого, второй у правого (мышь не участвует);
- без геймпада экран выбора героев напишет «нужен хотя бы один геймпад» и партию не начнёт.

Клавиши правого игрока остались (стрелки — ход, Enter — выстрел, правый Shift — удар, 9 0 - = — ячейки), но целиться ими нельзя — выстрел по прямой. По сети свой маг — клавиатура и мышь или свой геймпад. Клавиши работают в любой раскладке.

## Геймпады

Оба геймпада подключаются по USB-проводу, ничего настраивать не нужно.

- **Один геймпад — у правого игрока** (левый играет клавиатурой и мышью). **Два — первый у левого, второй у правого.** Чтобы поменять, переподключите их в нужном порядке.
- Правый стик — прицел.
- Внизу меню написано, какие геймпады найдены и кто за кого играет.
- У игрока с геймпадом ячейки инвентаря стоят ромбом, как кнопки: △ сверху, □ слева, ○ справа, ✕ снизу. С клавиатуры — в ряд 1–4.

Можно и по Bluetooth: беспроводной PS4-геймпад уже сопряжён, достаточно нажать на нём кнопку **PS**.

### Если геймпад не работает

1. Проверить, видит ли его система:
   ```bash
   ls /dev/input/js*
   ```
   На каждый геймпад должно быть устройство `js0`, `js1`.
2. Не видит → переподключить кабель, попробовать другой USB-порт.
3. Bluetooth не подключается → зажать **Share + PS** (на DualSense: **Create + PS**), пока подсветка не замигает часто, затем в «Настройки → Bluetooth» удалить «Wireless Controller» и выбрать его заново.
4. Геймпад подключили, когда игра уже запущена — игра подхватит его сама. Если нет, перезапустить игру.

## Ближний удар

- Кнопка: E у синего, правый Shift у красного, на геймпаде L1 или L2 (L2 — один удар на нажатие).
- Бьёт **только мобов**: всех, чей край не дальше 30 px от края мага, в любую сторону. Мага-соперника, двойников, пули и снаряды не задевает.
- 2 урона каждому, раз в 0,6 с, патроны не тратит; работает и под заморозкой, «не стреляет», запретом артефактов.
- Задетый моб злится на ударившего; убитый ударом — по общему правилу: на месте гибели остаются деньги.
- Взмах виден кольцом вокруг мага, звук — `assets/sounds/shoot03.mp3`.
- Настройки — `MELEE_DAMAGE`, `MELEE_RANGE`, `MELEE_COOLDOWN` в `duel/config.py`.

## Патроны

- В начале партии у каждого 20 патронов, верхнего лимита нет.
- Каждый выстрел тратит 1 патрон, веер из трёх пуль — тоже 1. Двойники стреляют бесплатно.
- Пачки по 20 патронов появляются в случайном месте земли игрока в среднем раз в 13 с (≈90 патронов в минуту) и лежат 10 с.
- Пачка подбирается сразу, в инвентарь не идёт — подбирается даже при полном инвентаре.
- Патроны кончились — счётчик в панели красный, при попытке выстрела всплывает «нет патронов».

## Мобы

- Мобы (обсидиановые големы) приходят **волнами**. Первая — сразу в начале партии, дальше каждые 15 с.
- Каждый моб появляется в **случайном месте арены мобов** — круга в центре поля. Заранее прицелиться нельзя.
- Первая волна — 4 моба по 3 жизни. В каждой следующей на 1 моба и на 1 жизнь больше. **Уже живые мобы при новой волне не меняются** — раненые не лечатся.
- Когда жизни мобов дошли до 6, каждая следующая волна приводит **на 2 моба больше** предыдущей (`MOB_LATE_EXTRA`).
- **Ограничения:** на поле не больше 16 мобов, у моба не больше 6 жизней.
- Когда волна дошла до максимума (16 мобов по 6 жизней), каждая следующая приходит **на секунду раньше**: 15 → 14 → … → 3 с между волнами.
- **Таймер волн** — в центре статуса, между инвентарями: номер волны и секунды до следующей.
- Пока их не трогают, мобы стоят на месте и ловят пули обоих игроков.
- Попал в моба — он идёт на тебя и встаёт прямо перед тобой (так его всегда можно достать прямым выстрелом). Если потом попал соперник — разворачивается на соперника.
- Дошёл — бьёт: −1 жизнь раз в секунду. Щит гасит удар моба так же, как пулю (тратит одно «попадание» щита).
- «Пули соперника медленнее» замедляет и мобов, которые идут на тебя; «быстрые пули» ускоряет мобов, которые идут на соперника. Множители — `SLOW_BULLET_FACTOR`, `FAST_BULLET_FACTOR`.
- **Дальнобойные мобы** — каждый третий моб волны (в первой волне — один из четырёх). Выглядят иначе: замшелые зелёные, с ядовитым кристаллом на голове. Разозлившись, не идут вплотную, а подходят на ~220 px и раз в 1,2 с стреляют зелёными снарядами. Стреляют, только если цель не дальше 280 px; снаряд пролетает не больше 280 px и исчезает. Снаряд снимает 1 жизнь, щит его гасит; замедление и «быстрые пули» действуют на снаряды так же, как на движение мобов; стены-зеркала и «сбиваешь пули» на них не действуют. Настройки — `MOB_RANGED_EVERY`, `MOB_RANGE`, `MOB_KEEP_DISTANCE`, `MOB_SHOT_SPEED`, `MOB_SHOT_COOLDOWN`.
- Над мобом — полоска жизней и число; цвет показывает, на кого он идёт (серый — ни на кого).
- Настройки — `MOB_*` в `duel/config.py`: `MOB_EVERY`, `MOB_EVERY_MIN`, `MOB_SPEEDUP`, `MOB_COUNT`, `MOB_HP`, `MOB_MAX`, `MOB_MAX_HP`, `MOB_AREA`.

## Деньги и магазины

Экспериментальная механика для локальной партии двух людей: убитые мобы дают деньги, а артефакты покупаются в магазинах, до которых нужно дойти.

- Обычный моб или страж при смерти оставляет на месте гибели **монету** `MONEY_DROP` = 10. Она подбирается касанием и лежит `MONEY_LIFETIME` = 20 с (рядом — таймер); не подобранная — исчезает.
- Запас денег виден в статусе у каждого игрока (монета и число). Деньги не тратятся сами; в новой партии баланс сбрасывается в 0.
- На поле **пять магазинов** (`SHOP_SPRITE_SIZE` = 40, `SHOP_RADIUS`):
  - `blue` и `red` — боковые лавки на землях игроков у краёв (`SHOP_X`), по центру по вертикали; продают артефакты земли своего героя;
  - `neutral_tl` — верхний левый угол нейтральной полосы; продаёт все общие артефакты;
  - `neutral_br` — нижний правый угол нейтральной полосы; продаёт все общие артефакты;
  - `arena` — центр арены мобов; продаёт снаряжение.
- Пока герой стоит на любом магазине, у его верхнего угла открывается **панель покупок** (`SHOP_WIDTH` = 48, `SHOP_ROW_H` = 26, `SHOP_PAD` = 4; высота — 8 + 26 × число товаров: 112 на 4, 190 на 7): левому игроку — верхний левый угол, правому — верхний правый. Внутри только значок и цена, вертикальным списком, без заголовка и пустых полей; ушёл — закрылась.
- **Покупать можно в любом магазине**, даже в чужом или нейтральном: важно, на какой постройке стоит герой. Деньги и инвентарь меняются только у покупателя.
- **Цены** — `ITEM_PRICES` в `duel/config.py`; обычные предметы стоят 20, тяжёлые — 30–40. Цена справа от значка; доступность по деньгам не подсвечивается. При наведении на товар видна обычная стрелка курсора.
- Постройка нарисована в пиксельном стиле (`assets/sprites/shop_building.png`, перерисовка — `tools/make_shop.py`), навес красится в цвет героя или остаётся серым у нейтральных. Панель рисуется кодом: тёмный прямоугольник с рамкой цвета стороны.
- Магазины — только в локальной партии 1×1. Сеть, 2×2, разминка, повторы, боты и обучение в этой итерации панелями не пользуются; постройки и деньги там видны, но покупки нет.

## Артефакты

Полное описание с значками — в игре, пункт меню «Артефакты».

- **Обычные артефакты больше не выпадают из мобов.** Единственный источник — магазины на поле. Артефакты, поставленные сценками и тестами, по-прежнему можно подобрать.
- Артефакт в магазине не лежит на поле: покупка сразу выдаёт его по обычным правилам инвентаря (см. «Деньги и магазины»).
- Подобранный артефакт ложится в свободную ячейку (их 4), а если все заняты — **в очередь** (без ограничения). Освободилась ячейка — в неё сразу встаёт первый из очереди. 3 следующих видно в ряд (с клавиатурой — под ячейками, с геймпадом — рядом с ромбом), «+N» — если в очереди больше.
- Лечение срабатывает сразу при подборе, минуя ячейки.
- **Улучшения оружия** (веер, волна, скорострельность, сбивание пуль) — тоже через ячейки, держатся 6 с (`WEAPON_TIME`). Разных одновременно не больше трёх (`WEAPON_MAX`): новое вытесняет то, у которого меньше всего времени.
- **Всё стакается:** повтор любого эффекта добавляет ему время; два щита подряд — вдвое больше и времени, и ударов; повторные двойники — новые до лимита (4) и ещё 15 с жизни живущим; стен может стоять несколько.
- **Статус:** всё, что сейчас действует на игрока, показано значками с таймерами во второй строке под его именем (оружие первым): щит — «удары×секунды», стены — «кол-во×секунды», двойники — «×кол-во». На поле — только кольца вокруг мага.
- Рамка: зелёная — защита, синяя — атака, оранжевая — бьёт по сопернику.
- Разные эффекты действуют вместе (заморозка + «не стреляет», волна + веер + скорость).
- Дебаффы соперника снимаются только временем или очищением.
- На двойников переходят эффекты хозяина: щит, все улучшения оружия, ×2, уменьшение, скорость, «не стреляет».

| Группа | Артефакт | Что делает |
|---|---|---|
| Защита | щит | гасит 5 пуль или держится 7 с — что раньше; удары и секунды видны в статусе |
| | лечение | +3 жизни сразу при подборе |
| | очищение | снимает с тебя и двойников все дебаффы; работает даже под запретом артефактов |
| | уменьшение | ты меньше в 2 раза, 7 с |
| | убрать пули соперника | все пули соперника исчезают с экрана |
| | пули соперника медленнее | его пули и мобы, которые идут на тебя, — примерно вдвое медленнее, 7 с |
| Оружие (6 с) | веер | каждый выстрел — три пули веером, патрон один |
| | пули волной | твои пули летят синусоидой |
| | скорострельность | пауза между выстрелами 0,1 с вместо 0,25 |
| Атака | двойники | два мага-двойника сами ходят и стреляют, умирают с одного попадания |
| | быстрые пули | твои пули и мобы, которые идут на соперника, — в 1,6 раза быстрее, 7 с |
| | стена-зеркало | пули соперника отражаются и становятся твоими, твои пролетают насквозь; мобы сквозь неё не проходят и обходят её; 8 с |
| Дебаффы | соперник ×2 | соперник больше в 2 раза, 7 с |

| | соперник: управление наоборот | вверх и вниз меняются местами, 5 с |
| | соперник без артефактов | не может использовать артефакты (кроме очищения), 5 с; подбирать может |

## Настройки

Все числа и цвета — в `duel/config.py`:

- громкость — `MUSIC_VOLUME`, `SHOOT_VOLUME`;
- жизни — `MAX_HP` (и в «Тесте с ботом»; больше — `/hp`), лечение — `HEAL_AMOUNT`;
- щит — `SHIELD_HITS` и `DURATION["shield"]`;
- патроны — `START_AMMO`, `AMMO_PACK`, `AMMO_SPAWN`, `AMMO_LIFETIME`;
- длительность эффектов — словарь `DURATION`;
- мобы и их награды — `MOB_*`; деньги — `MONEY_DROP`, `MONEY_RADIUS`, `MONEY_LIFETIME`, `MONEY_COLOR`; магазины — `SHOP_WIDTH`, `SHOP_ROW_H`, `SHOP_PAD`, `SHOP_SPRITE_SIZE`, `SHOP_RADIUS`, `SHOP_X`, `ITEM_PRICES`.

Ещё: мёртвая зона стика — `PAD_DEAD` в `duel/gamepad.py`.

## Музыка и звуки

Музыка лежит в `assets/music/`, звуки — в `assets/sounds/`. Музыка подбирается по имени, так что новый трек достаточно положить в папку с подходящим именем:

| Файлы | Когда играет |
|---|---|
| `assets/music/menu-*.mp3` | меню и справка, по кругу |
| `assets/music/background-*.mp3` | игра и ролик при старте (`intro`): треки вперемешку; кончился один — начинается другой |
| `assets/sounds/shoot01.mp3` / `shoot02.mp3` | выстрел синего / красного |
| `assets/sounds/shoot03.mp3` | ближний удар |

Громкость — `MUSIC_VOLUME`, `SHOOT_VOLUME`. Откуда треки — `assets/music/SOURCES.md` (музыку из `raw/` кладём сюда руками: `tools/import_sounds.py` — только для звуков).

## Ролики

Ролик — сцены из игры одна за другой, с переходами и субтитрами (движок — `duel/movie.py`, сцена — `duel/scene.py`, та же, что у сценок «Обучения»). Папка `assets/movies/<ролик>/`:

- `movie.json` — сценарий: сцены (длина, герои, камера, кто где стоит, мобы) и что в них происходит по времени — вызовы внутреннего API сцены: `move`, `walk_to`, `aim`, `fire`, `melee`, `cast`, `teleport`, `appear`, `vanish`, `hero`, `mob`, `drop`, `gear`, `camera`, `follow`, `shake`, `speed`. Пример: `{"t": [1, 3], "every": 0.35, "do": "fire", "who": "red", "at": "blue"}`. Описание всех полей — в начале `duel/scene.py` (сцена) и `duel/movie.py` (ролик).
- **Сцена-надпись** (`"title": "zoom"` или `"slide"`, движок — `duel/movie_title.py`): слово (по умолчанию — название игры), буквы которого — дырки, а за ними идёт настоящий бой двух ботов (`"battle"`: зерно, герои, уровень, сколько секунд прокрутить заранее, участок поля). `zoom` — надпись летит из глубины, камера летит прямо в левую ножку «U» и проходит сквозь неё — открывается поле; пока летит, музыка нарастает (`zoom_time`). `slide` — надпись въезжает слева, стоит и трясётся, уезжает вправо (`slide`: въезд, стоит, выезд; `shake` — сила тряски). Вокруг букв — золотой ободок. Ролик `intro` начинается с `zoom` и кончается `slide`.
- **Сцена «выбор героя»** (`"pick": {"blue": "fire", "red": "frost", "every": 0.3, "lock": [2.3, 2.7]}`, движок — `duel/movie_pick.py`): настоящий экран выбора, по которому сами листаются герои (шаг `every`), в моменты `lock` левый и правый выбирают. В `intro` — вторая сцена, «Выбирай героя!».
- Переходы между сценами движок добавляет сам: `fade` (через чёрный), `dissolve` (растворение), `flash` (белая вспышка), `wipe` (шторка), `cut` (склейка). Кадр — 16:9, сверху и снизу чёрные полосы; камера не искажает (участок расширяется до 16:9).
- `subs.ru.srt`, `subs.en.srt`, … — субтитры в формате SRT, время — от начала ролика. Новый язык — просто новый файл; нет файла для языка игры — показываются английские. Показываются внизу, белым на чёрном.
- `"music"` в сценарии — маска файлов в `assets/music` (например `"intro-*.mp3"`); нет — музыки нет, слышны звуки сцен.

Смотреть: `.venv/bin/python main.py --movie intro --windowed`; Esc — пропустить, F5 — перечитать файлы и начать сначала (удобно, пока правишь сценарий). Ролик `intro` — промо-ролик (черновик), показывается при каждом запуске, пока в «Обучение» → «Об игре» стоит галка «Показывать при старте» (настройка `intro_on_start`); там же — «Смотреть ролик» (идеи — `docs/ideas.md`).

### Матч и приложение

Игра разделена на две части (так проще будет играть по сети — см. «Сетевая версия»):

- **Матч** (`duel/match.py`, класс `Match`) — правила и состояние одной партии. Ничего не знает про окно, звук, клавиши и язык. Один шаг: `events = match.step(1/60, {"blue": Command(...), "red": Command(...)})` — получает команды игроков, возвращает события: `("shot", "blue")`, `("pickup", "red", "shield")`, `("used", кому, артефакт)`, `("money", кто, сколько)`, `("buy", кто, артефакт)`, `("ammo", кто, 20)`, `("no_ammo", кто)`, `("melee", кто)`, `("mob_dead", x, y)`, `("wave", номер, мобов, жизней)`.
- **Приложение** (`duel/game.py`, класс `Game`) — окно, меню, настройки. Клавиатуру и геймпады превращает в команды, делает шаги матча ровно 60 раз в секунду (такт фиксированный, от скорости кадров не зависит), события превращает в звук и всплывающие надписи на языке игрока. Новая партия — новый `Match`. Рисует `screens.py`, читая `game.match`.
- **Случайность** — только из генератора матча `match.rng` (зерно: `Match(seed=...)`). Одно зерно и те же команды → та же партия. Общий `random` в правилах не использовать.
- **Номера объектов**: у мобов, пуль, снарядов, артефактов, пачек, денег, стен, двойников — `id` из счётчика матча (выдаётся в конце шага); маги — `"blue"` / `"red"`.
- **Снимок** (`duel/snapshot.py`): `snapshot(match)` — словарь из чисел, строк, списков: маги (место, размер, жизни, деньги, патроны, эффекты с таймерами, ячейки, очередь), пули, мобы, снаряды, артефакты, пачки, деньги, стены, двойники, волна, победитель. Приложение берёт снимок после каждого такта (`game.snap`), и **экран рисует только по нему** — так же будет рисовать клиент в сети. Матч, сущности и снимок не загружают pygame.

Как добавлять механику: **правило — в матч** (`match.py`, сущности — `entities.py`), **вид и звук — в приложение**. Если новое надо видеть на поле: поле в снимке (`snapshot.py`) → рисование по снимку (`render.py`, строка в `draw_field`) или в статусе (`screens.py`). Если игроку надо что-то показать или проиграть звук — матч делает `self.emit("ключ", ...)`, а `Game.handle_events` решает, как это показать. Текст и цвет в матч не попадают.

Новый артефакт: строка в `ITEMS` и `HELP_SECTIONS` и описание в `item_help` (`duel/items.py`), значок в `duel/icons.py`, действие в `Match.apply_item` (`duel/match.py`).

Тесты правил работают на фикстуре `match` (матч без окна, шаги — `step(match, секунды, moves={"blue": (0, -1)})`), тесты меню, ввода и отрисовки — на фикстуре `game`.

**Отпечаток партии** (`tools/fingerprint.py`): партии двух случайных ботов с фиксированными зёрнами, хеш состояния каждую секунду. Тест сравнивает его с `tests/data/fingerprint.json` — так видно, что перестройка кода не поменяла поведение. Если правила или баланс меняются **намеренно**, эталон перезаписать:

```bash
.venv/bin/python tools/fingerprint.py --save tests/data/fingerprint.json
```

## Разработка по спецификациям (OpenSpec)

В проекте подключён [OpenSpec](https://github.com/Fission-AI/OpenSpec) — spec-driven development: сначала спецификация изменения, потом код.

- CLI: `openspec` (стоит в `~/.local/bin`, версия 2.1). Обновить: `npm install -g --prefix ~/.local @fission-ai/openspec@latest`, потом `openspec update` в проекте.
- Папки: `openspec/specs/` — текущие спецификации игры, `openspec/changes/` — предлагаемые изменения, `openspec/changes/archive/` — завершённые. `openspec/config.yaml` — контекст проекта и правила (язык артефактов — русский).
- Скиллы для Claude Code лежат в `.agents/skills/` (ссылки — в `.claude/skills/`).
- Текущая игра описана в `openspec/specs/` (24 раздела): `battlefield` (поле и движение), `shooting` (стрельба, жизни, победа), `ammo`, `artifacts` (магазин, инвентарь, очередь, стаки), `artifact-effects` (что делает каждый артефакт), `mobs`, `melee` (ближний удар), `controls`, `menus`, `settings` (языки), `hud` (статус), `audio-graphics`. Проверка формата: `openspec validate --specs --strict`.

Порядок работы в Claude Code:

1. `/openspec-propose <что хотим>` — создаёт `openspec/changes/<имя>/`: `proposal.md` (что и зачем), `specs/…` (что должна делать игра — дельта к спецификации), `design.md` (как), `tasks.md` (шаги). Код при этом не трогается.
2. Прочитать, поправить, обсудить.
3. `/openspec-apply-change` — реализация по `tasks.md`.
4. `/openspec-archive-change` — изменение вливается в `openspec/specs/`, папка уходит в архив.

Ещё: `/openspec-explore` — обдумать идею без изменений в файлах. Полезные команды: `openspec list` (изменения), `openspec list --specs`, `openspec view` (дашборд).

Телеметрия OpenSpec отключена: `openspec config set telemetry.enabled false`.

## Игра по сети

Устроено как у настоящих онлайн-игр: на **сервере** — **лобби** (кто в сети, какие партии идут), а каждая партия идёт отдельно (двое и зрители). На одном сервере одновременно идут несколько партий. Сервером может быть сама игра («Создать свой сервер») или отдельная программа на домашнем устройстве (`python -m duel.server`, см. ниже) — для игроков разницы нет.

**Из меню — «Играть по сети»:**

1. **Серверы.** Сверху — свой сервер (если создан), ниже — найденные в сети: имя, адрес, «партий: N, игроков: M» (или «другая версия игры»). Первый выбирается сам — сразу Enter (✕); другой — ↑/↓ или крестовиной. Дальше — строка ручного ввода адреса (цифры, точки, любая раскладка; последний удачный адрес запоминается) и **«Создать свой сервер»**: сервер запускается внутри игры, и ты сразу в его лобби. Свой сервер работает, пока открыта игра (или до «Остановить свой сервер» в этом же списке); его видят все в сети.
2. **Лобби сервера.** Слева — **игроки в сети**: имя (★ — с аккаунтом) и что делает — «в лобби», «ищет соперника», «выбирает героя», «в партии», «смотрит». Справа — **идущие партии**: «Папа (Огонь) — Маша (Тьма)», сколько идёт, зрители. Сверху справа — аккаунт. Внизу — кнопки:
   - **вызвать** игрока — щелчок (или Enter) по нему: у него всплывает окно «… вызывает вас на поединок» — «Принять» / «Отказаться» (20 секунд на ответ); у тебя — «Ждём ответа…» (Esc — отменить);
   - **«Ищу соперника»** (F, △) — двое ищущих сводятся сразу; ещё раз — перестать искать;
   - **«Играть с ботом»** (B) — партия против бота на сервере;
   - **«Разминка»** (T, Share) — партия против бота на своём компьютере, пока ждёшь: можно одновременно искать соперника; вызов или найденный соперник её прерывают;
   - **смотреть** партию — щелчок (Enter) по ней.
3. **Выбор героя.** Как за одним компьютером: свой ряд — ←/→ (или щелчок) и Enter (или щелчок по выбранному) — «готов»; ряд соперника видно. Одного героя взять нельзя. Оба готовы — отсчёт 3–2–1 и бой. Вызвавший — синий, принявший — красный.
4. **После партии** — «Реванш» (R, ✕; нажали оба — снова выбор героя) или «В лобби» (Esc). Ушёл один — второй тоже в лобби с надписью «Соперник ушёл».
5. **Esc — шаг назад:** в партии — пауза, а «Покинуть партию» на ней (и Esc на выборе героя) — в лобби сервера, из лобби — к серверам, из серверов — в меню.
6. **Обрыв связи.** Пропал Wi-Fi (или 3 секунды тишины) — партия на паузе, у соперника «…: связь потеряна — ждём N с». Отключившийся сам переподключается раз в секунду на своё место. Не вернулся за 30 секунд — партия закрывается, все в лобби. Сервер закрылся — все возвращаются к списку серверов с надписью «Сервер закрылся».

Картинка идёт с задержкой около 0,1 секунды и плавно — так незаметны неровности Wi-Fi.

**Зрители.** Щелчок по идущей партии в лобби — **зритель**: видит выбор героя и партию, снизу «Вы зритель», управлять ничем не может; Esc — в лобби. До 8 зрителей на партию; в списке партий видно «зрителей: N».

**Вход на сервер.** В первый раз — экран **«Как войти?»**: имя и «Играть как гость» или «Войти в аккаунт» / «Создать аккаунт» (имя 2–16 символов, пароль от 4). Выбор запоминается для каждого сервера на этом компьютере: вошёл в аккаунт — дальше вход сам, по сохранённому ключу («Входим как …», пароль не нужен); выбрал гостя — сразу в лобби. На другом компьютере — свой ключ: там войти один раз. В лобби справа вверху — «Вы: … · выйти» / «Гость: … · войти» — снова «Как войти?». Имя, занятое аккаунтом, у гостя показывается с пометкой «(гость)». После 10 неверных паролей с одного компьютера — пауза 5 минут.

У каждого сервера свои аккаунты: свой сервер в игре хранит их в `server.db` рядом с настройками, `python -m duel.server` — в `~/.local/share/spellgunners/server.db` (или `--db ПУТЬ`). На сервере хранятся только хеши паролей (scrypt с солью), сами пароли — нигде.

Команды админа (на компьютере сервера):

```bash
.venv/bin/python -m duel.server users list            # аккаунты: имя, когда создан, сколько входов
.venv/bin/python -m duel.server users reset Маша      # новый пароль (печатается), старые входы — всё
.venv/bin/python -m duel.server users ban Маша        # заблокировать (unban — вернуть), delete — удалить
```

**Трафик.** Снимок партии — ~3,6 КБ, 30 в секунду; игра просит сжатый поток (zlib на всё соединение), и к ней уходит ~4 КБ/с вместо ~110 КБ/с (~14 МБ в час на игрока вместо ~400). Старые игры и старые серверы работают без сжатия.

**Логи сервера.** `python -m duel.server` пишет в консоль и в `logs/server.log` рядом с настройками (`--logs ПАПКА` — другая папка; 5 файлов по 5 МБ): время, уровень и что случилось — входы и выходы, комнаты, начало партии, **итог** («партия окончена: победил Маша (fire); … 94 с, волна 3, жизни: blue 4, red 0, зерно …»), раз в минуту боя — связь игроков (пинг, снимков/с, джиттер, FPS), чат, тестовые команды, ошибки. Если в комнате случилась ошибка, рядом появляется `room-error-<дата>-<комната>.json`: зерно, герои, такт, состояние магов и команды игроков за последние 5 секунд — по нему партию можно повторить у себя. Ошибки ищутся так: `grep ERROR ~/.config/duel/logs/server.log`. **Разрывы связи**: при обрыве сервер пишет `[комната N] blue (имя): обрыв — тишина 3.2 с / соединение закрыто; фаза …, последняя связь: пинг …` и держит место 30 с (партия на паузе); вернувшийся клиент (и в браузере) присылает журнал связи — строка «вернулся, отчёт о разрыве: …» и файл в `logs/net-reports/` (последние 200): раз в 5 с пинг, снимки, джиттер, FPS; причина обрыва (код закрытия WebSocket или тишина), «вкладка скрыта/видна», «кадра не было N с» (вкладка в фоне — частая причина), попытки. Не вернулся — партия сохраняется повтором («повтор оборванной партии»). На официальном сервере: `ssh <сервер> 'grep -n "обрыв\|отчёт о разрыве\|не вернулся" /var/lib/spellgunners/logs/server.log | tail -40'`, журналы — `/var/lib/spellgunners/logs/net-reports/`. Свой сервер внутри игры пишет в `game.log` с пометкой `[сервер]`.

**Сервер в интернете (AWS Lightsail).** Пошагово — [`docs/deploy-aws.md`](docs/deploy-aws.md): от аккаунта AWS до игры по `wss://имя.duckdns.org/`. Файлы развёртывания — `deploy/`: служба systemd в песочнице, ежедневная копия базы аккаунтов, Caddy (сертификат и `wss://`), `install.sh` и `update.sh`. Для сервера в интернете `python -m duel.server` включает лимиты: не больше 6 соединений с адреса (`--max-per-ip`), 150 сообщений в секунду от соединения (`--msg-rate`), 3 новых аккаунта в час с адреса; за прокси на этой же машине настоящий адрес игрока берётся из `X-Forwarded-For`. `--host 127.0.0.1` — слушать только эту машину (наружу — через Caddy), `--no-discovery` — не отвечать на поиск в локальной сети.

**Жив ли сервер.** `python -m duel.server --status-port 5557` включает страницу состояния (только для этого компьютера; `--status-host 0.0.0.0` — для всей сети): `curl http://127.0.0.1:5557/` — версия, сколько работает, комнаты, игроки, законченные партии, ошибки за час и последняя, длительность тактов; `curl http://127.0.0.1:5557/health` — `ok` (200), пока сервер жив, и 503, если главный цикл завис. Годится для проверки по расписанию (`cron`, systemd-таймер).

**Отчёты о падениях от игроков.** Если у игрока упала игра, при следующем запуске она спросит, можно ли отправлять такие отчёты (поменять — Настройки → «Отчёты о падениях серверу»). С разрешения отчёт уходит серверу при подключении — без имени пользователя и путей к его папкам. Сервер складывает их в `logs/client-crashes/` (не больше 3 с одного подключения), в `server.log` — строка «отчёт о падении игры v…».

⚠ Пока соединение **не шифруется**: дома это нормально, но выставлять сервер с аккаунтами в интернет без шифрования нельзя — пароль можно подсмотреть по дороге. Шифрование (TLS с настоящим сертификатом) — шаг переноса сервера в интернет.

**Если не подключается:**

- «на этом адресе игра не создана» — на том компьютере не нажали «Создать игру» или адрес набран с ошибкой;
- «компьютер не отвечает» или игра не появляется в списке — компьютеры в разных сетях, или брандмауэр. Linux с `ufw` на компьютере с игрой: `sudo ufw allow 5555/tcp` и `sudo ufw allow 5556/udp` (5556 — поиск игр). Windows при первом запуске спрашивает разрешение — разрешить для **частных** сетей; если отказали — «Брандмауэр Защитника Windows» → «Разрешить взаимодействие с приложением» → отметить игру;
- сервер не появляется в списке (или мигает), но по адресу подключается — сеть (mesh-роутер, раздача с телефона) теряет широковещательные пакеты поиска: подключиться по адресу один раз — дальше игра спрашивает этот сервер напрямую, и он виден в списке всегда (помнит 5 последних серверов);
- «другая версия игры» — обновить игру на обоих компьютерах (`git pull`);
- «v0.7.4, старее» в списке серверов или жёлтая строка в лобби «Сервер … старее игры — обновите сервер. Не работает: …» — протокол тот же, играть можно, но перечисленное (тестовые команды и т.п.) на этом сервере не работает, пока его не обновят; «новее — обновите игру» — наоборот. Версию каждой подключившейся игры сервер пишет в свой лог;
- «Не удалось создать игру: порт 5555 занят» — уже запущена другая игра или сервер; закрыть её.

**Через интернет (друзья в другом доме) — Tailscale.** Игра сама в интернет не ходит, но Tailscale делает «общую домашнюю сеть» поверх интернета — бесплатно, без настройки роутера:

1. На **обоих** компьютерах поставить Tailscale (<https://tailscale.com/download>; Ubuntu: `curl -fsSL https://tailscale.com/install.sh | sh`, потом `sudo tailscale up`; Windows — установщик) и войти. Проще всего — **одним** аккаунтом на оба компьютера; если аккаунты разные — хозяин сети приглашает второго (в панели Tailscale «Share» / «Invite users»).
2. Узнать адрес компьютера, который создаёт игру, в сети Tailscale: `tailscale ip -4` (Windows — значок Tailscale в трее), вида `100.x.y.z`.
3. Первый — «Играть по сети» → «Создать свой сервер». Второй — «Играть по сети», в строке ручного ввода **набрать адрес `100.x.y.z`**: поиск серверов по Tailscale не работает (он шлёт широковещательный пакет, а Tailscale такие не передаёт).
4. Не подключается: на Linux с `ufw` — `sudo ufw allow in on tailscale0 to any port 5555 proto tcp`; на Windows — разрешить игру в брандмауэре и для **общественных** сетей (сеть Tailscale Windows может считать общественной). Проверить связь: `tailscale ping 100.x.y.z`.

Комфортно, пока задержка небольшая: `tailscale ping` показывает до ~50 мс — играется как дома; 100+ мс — свой маг слушается с запаздыванием (это этап 7 в дорожной карте). Трафик — около 1,5 Мбит/с от создателя игры к гостю.

**Два окна на одном компьютере** (проверить сеть одному или играть с двумя геймпадами): запустить игру из терминала дважды в окне — `.venv/bin/python main.py --windowed` и `.venv/bin/python main.py --windowed --pad 1`. В первом окне «Создать игру», во втором «Подключиться» к `localhost`. Клавиатура достаётся окну в фокусе, а геймпад клиента работает и без фокуса (`--pad N` — номер своего геймпада, с 0).

**Сервер без окна** (например, на отдельном компьютере):

```bash
.venv/bin/python -m duel.server                 # сервер с лобби на порту 5555
.venv/bin/python -m duel.server --name "Дом"    # имя в списке серверов (иначе — имя компьютера)
.venv/bin/python -m duel.server --db ~/дом.db   # где хранить аккаунты
.venv/bin/python -m duel.server --bot           # (для тестов) в новых партиях свободное место — бот
.venv/bin/python -m duel.server --port 6000
.venv/bin/python main.py --connect 192.168.1.5 --windowed   # подключиться из терминала
```

Как устроено: поиск — UDP-вопрос «кто здесь сервер?» на порт 5556 всей сети (дважды в секунду) и напрямую знакомым серверам, сервер отвечает именем и портом (`duel/discovery.py`); протокол игры — TCP, сообщения JSON по одному в строке, версия 7: лобби сервера (аккаунты по желанию, игроки и партии, вызов, поиск соперника, бот, смотреть), в комнате — место с ключом для возврата, готовность (`duel/net.py`); сервер шагает матч 60 раз в секунду и шлёт снимок 30 раз в секунду (`duel/server.py`); клиент сглаживает движение между снимками (`duel/interp.py`). План дальнейших этапов (лобби, переподключение, зрители, портал) — в [`docs/network-roadmap.md`](docs/network-roadmap.md).

## Пиксельная графика: как редактировать

Вся графика — обычные PNG в `assets/sprites/`. Это и есть исходники: правите их в пиксель-редакторе, игра берёт их как есть.

| Файл | Что это | Размер |
|---|---|---|
| `mage.png` | маг с автоматом, смотрит вправо, в ледяных (синих) цветах | 32×32, прозрачный фон |
| `bg_ice.png` | земля синего, лёд | 125×160, игра увеличивает в 4 раза |
| `bg_lava.png` | земля красного, лава | 125×160, игра увеличивает в 4 раза |
| `bg_mob.png` | полоса мобов посередине, обсидиан | 50×160, игра увеличивает в 4 раза |
| `mob.png` | моб (обсидиановый голем), смотрит вправо | 16×16, прозрачный фон |
| `mob_ranged.png` | дальнобойный моб (зелёный, с кристаллом), смотрит вправо | 16×16, прозрачный фон |

**Маг рисуется один раз.** Красного игра делает из `mage.png` сама: заменяет четыре цвета команды и зеркалит. Поэтому любая правка рисунка сразу попадает в обоих. Цвета команды (заменяются у красного):

| На рисунке (синий) | У красного | Где |
|---|---|---|
| `#b9d4f0` | `#dc3c32` | мантия и шляпа |
| `#6e96cd` | `#8c1e23` | тень |
| `#f0f8ff` | `#ff8c64` | блик |
| `#78e1ff` | `#ffd646` | кристалл на шляпе → звезда |

Чтобы деталь была цвета команды — рисуйте её одним из этих четырёх цветов. Любой другой цвет будет у обоих магов одинаковым. Таблица замены — `MAGE_RED_PALETTE` в `duel/config.py`.

**Порядок работы:**

1. Поставить редактор (один раз): `sudo snap install pixelorama`. Подойдут и LibreSprite, Aseprite.
2. Запустить игру в окне (F11) и открыть PNG в редакторе рядом.
3. Нарисовать, сохранить PNG (тот же размер, формат PNG, прозрачный фон у мага).
4. В игре нажать **F5** — картинки перечитаются с диска, изменения видны сразу.

Новый размер мага (например 48×48) тоже можно — игра масштабирует его под круг попадания. Попадания считаются по кругу, не по картинке; насколько картинка больше круга — `SPRITE_TO_HITBOX` в `duel/sprites.py`.

**Скрипт `tools/make_sprites.py`** создаёт начальные версии картинок. Существующие файлы он не трогает:

```bash
.venv/bin/python tools/make_sprites.py                       # дорисовать недостающие PNG
.venv/bin/python tools/make_sprites.py --preview /tmp/p.png  # крупный предпросмотр обоих магов на фонах
.venv/bin/python tools/make_sprites.py --force               # перерисовать всё с нуля — ваши правки пропадут!
```

**Пауза по сети.** P — сразу «Пауза для всех», снова P — «Снять паузу». Esc открывает своё меню, игра при этом идёт («Меню — игра идёт!»), соперник видит «<имя> в меню». В меню — «Пауза для всех»: партия встаёт у обоих (3 паузы на игрока за партию, 5 с после продолжения новую ставить нельзя). Снять паузу может любой — «Снять паузу», потом отсчёт 3-2-1. Числа — `PAUSE_LIMIT`, `PAUSE_RESUME`, `PAUSE_COOLDOWN` в `duel/config.py`. Сервер нужен новый: старый паузу не поддерживает.

**Звуки с Pixabay.** Положить файл в `raw/` с именем `<оригинальное имя>.<назначение>.mp3` и запустить `.venv/bin/python tools/import_sounds.py` — он копирует в `assets/sounds/<назначение>.mp3` и пишет источник в `assets/sounds/SOURCES.md` (`raw/` в git не идёт). Подключение — `ITEM_SOUNDS` (артефакт), `LOOP_SOUNDS` (цикл: шаги, чужая земля, ледяная тропа), `HIT_SOUND` в `duel/config.py`. Обрезка, плавность, усиление, склейка шагов — `assets/sounds/edits.json` (файлы не меняются; применяется при запуске игры). В справке звук сценки обрывается при смене пункта.

**Невидимость** — исчезает в мареве с искрами и кольцом света (видят все), себе и за одним компьютером — дрожащий силуэт, в конце проявляется из искр (`assets/effects/invisible.json`). Сценка `invisible`.

**Чат по сети.** T — написать сопернику, Enter — отправить, Esc — отмена; пока пишешь, маг стоит. Сообщения — внизу слева (гаснут через 10 с) и пузырём над магом; видят оба игрока и зрители. Работает в бою, на выборе героя и после партии. Ограничения сервера — `CHAT_MAX`, `CHAT_GAP` в `duel/config.py`; сервер нужен новый.

**Команды чата** (строка с `/`, выполняются у себя): `/net` (`/сеть`) — статистика связи вверху слева, своя и соперника: пинг, снимков в секунду (норма 30), джиттер, буфер плавной анимации, FPS; `/pause` (`/пауза`) — как P; `/disconnect` (`/дисконнект`) — оборвать связь, чтобы проверить переподключение; `/help` — список. Пинг клиент меряет раз в `PING_EVERY` секунд.

**Тестовые команды** — только в игре с ботом: «Тест с ботом» в меню (ты синий, красным играет бот; жизней — как в обычной партии), разминка в лобби, сетевая партия «Играть с ботом». T и:
- `/give lasso` или `/give лассо` — артефакт себе, `/give lasso bot` — боту; `/items` — коды всех артефактов;
- `/bot stop` — бот ничего не делает (мишень), `/bot fire` — стоит и стреляет прямо вперёд, `/bot play` — снова играет, `/bot use 1` — бот применяет ячейку 1;
- `/bot stand` — не ходит, `/bot noshoot` — не стреляет (остальное как обычно), `/bot walk`, `/bot shoot` — снова;
- `/drops off` — мобы не роняют деньги, `/drops on` — роняют;
- `/ammo` — пачка патронов себе (20), `/ammo 100` — сто, `/ammo 5 bot` — боту.
- `/hp 1000` — себе 1000 жизней (столько и максимум), `/hp 50 bot` — боту; от 1 до 99999.

**Консоль** — `~` (перед 1): внизу поля история, ввод не закрывается после Enter, Esc или `~` — закрыть, PgUp/PgDn — листать. T — одна строка. Работают и на паузе. Клавиши паузы (P) и чата (T) переназначаются в «Клавишах».
Режим бота — до конца партии. Против человека команды не работают (сервер их тоже не принимает).

## Аддоны (только настольная игра)

«Настройки → Дополнительно → Аддоны…»: список, ◀ ▶ — включить/выключить (запоминается), под включённым — его экраны. Встроенные (выключены по умолчанию): «Лаборатория» (прогоны лаборатории баланса из игры) и «Радиусы» (образец рисования на поле: дальность удара и огненного круга вокруг своего мага). Свои — в `~/.config/duel/addons/` (Windows — `%APPDATA%\duel\addons\`): файл `имя.py` или папка `имя/__init__.py`.

Аддон — обычный Python с полными правами на компьютере: ставить только свои и доверенные. Партию он не меняет — видит снимок (то же, что игрок; по сети правила считает сервер). Ошибка в аддоне игру не роняет: он выключается, текст ошибки — в списке (полностью — в `game.log`). API v0 — нестабильный.

```python
NAME = "Мой аддон"
DESCRIPTION = "что делает"
API_VERSION = 0

def register(api):
    api.add_screen("Мой экран", build)        # экран в списке аддонов
    api.on_draw_field(draw)                   # рисовать поверх поля

def build():                                   # каждый кадр — строки экрана (как настройки)
    return [api.Label("текст"), api.Choice("выбор", ["a", "b"], "a", on_change),
            api.Number("число", 5, 0, 10, 1, on_change), api.TextInput("строка", "", on_change),
            api.Button("кнопка", on_press), api.Progress(0.5, "50 %"), api.TextView(["много", "строк"])]

def draw(pen, snap, me):                       # pen.circle/line/rect/text(…, alpha=), координаты поля
    for p in snap["players"]:
        pen.circle(p["x"], p["y"], 60, (255, 255, 255), alpha=80)
```

Ещё: `api.run_background(fn)` — `fn(progress, stop)` в потоке (вернёт Job: `value`, `text`, `running`, `request_stop()`); `api.storage` и `api.save()` — свои настройки; `api.replays_folder()`, `api.open_replays(папка)`; `api.log`; `unregister()` в модуле — вызывается при выключении. Подробно — docstring `duel/addons.py`, примеры — `duel/addons_builtin/`.

## Скорость сервера (не в CI)

Запускать руками время от времени, особенно после изменений в партии, сети и сервере — смотреть, нет ли деградации.

```bash
cd ~/projects/fast-game
.venv/bin/python tools/perf.py --duels 6 --teams 2      # 20 человек: 6 партий 1×1 + 2 партии 2×2, 90 с — основной
.venv/bin/python tools/perf.py                          # 40 человек: 10 × 1×1 + 5 × 2×2 — с запасом
.venv/bin/python tools/perf.py --duels 6 --teams 2 --seconds 180   # дольше: поздние волны мобов тяжелее
.venv/bin/python tools/perf.py --duels 6 --teams 2 --history       # прошлые прогоны этого сценария
```

Что делает: поднимает свой сервер на свободных портах (база и логи — во временной папке), подключает поддельных игроков по настоящему протоколу (вызов, выбор героя, бой: ходят, целятся, стреляют 60 раз в секунду, реванш), первые 8 с не считает (разгон), потом каждые 10 с меряет.

Отчёт: на каждый показатель — сейчас (цвет по порогам: зелёное хорошо, жёлтое на грани, красное плохо), прошлый прогон того же сценария (▲▼ — хуже/лучше, разница), лучший за всё время (дата, коммит) и пороги. Внизу — список «плохо». Пороги — в начале `tools/perf.py` (бюджет такта — 16,7 мс; норма — 30 снимков в секунду).

- **такт сервера** (средний, p99, самый долгий) — сколько занимает один шаг всех партий; дольше 16,7 мс — снимки опаздывают, у игроков рывки;
- **процессор сервера** — % одного ядра (сервер однопоточный: к 100% — потолок);
- **снимков в секунду** (худший 10-секундный отрезок) и **паузы между снимками** (p99, max) — что видят игроки;
- **снимок** и **трафик на игрока** — для дальних и медленных подключений.

История — `~/.config/duel/logs/perf/*.json`; сравниваются только прогоны одного сценария (число партий и длительность). Сервер и нагрузка — на одном компьютере, нагрузка тоже ест процессор: числа хуже, чем на настоящем сервере, и шумят от прогона к прогону (особенно худшие значения) — смотреть на тенденцию, а сомнительное повторить.

Нагрузка без отчёта — на любой сервер (свой запущенный или, по договорённости, боевой в тихое время):
`.venv/bin/python tools/load.py --address host:5555 --duels 6 --teams 2 --seconds 120 --status http://127.0.0.1:5557/`
(`--status` — страница состояния, если она доступна с этого компьютера; на боевом — только с самого сервера).

## ИИ-бот: обучить и проверить (запускать самому)

Нужны numpy и torch в `.venv` (уже стоят). Игре они не нужны — только для обучения. Обучение — 1×1 (2×2 ИИ не умеет: за напарников в 2×2 играет бот на правилах).

```bash
cd ~/projects/fast-game
# обучить с нуля за героя (по умолчанию — все ядра, кроме одного; можно оставить на ночь)
.venv/bin/python tools/ai_train.py --name fire-v3 --hero fire --minutes 60
# продолжить то же обучение (тот же --name)
.venv/bin/python tools/ai_train.py --name fire-v3 --hero fire --minutes 60 --resume
# за всех героев сразу (дольше)
.venv/bin/python tools/ai_train.py --name all-v1 --minutes 240

# проверить: 300 партий против сложного бота на правилах, подробно (герои, артефакты, длина партий)
.venv/bin/python tools/ai_eval.py --name fire-v3 --hero fire --opponent hard --details
# в лаборатории баланса: ИИ синим против сложного красным
.venv/bin/python tools/lab.py report --games 600 --blue ai:fire-v3 --red hard
```

Что видно в терминале при обучении: раз в обновление — строка журнала: решений, партий, % побед и против кого (лёгкий → обычный → сложный: следующий соперник, когда ИИ выигрывает больше `--promote`, 0,6; после сложного — пополам сложный и свои прошлые версии), награда, длина партии, энтропия (уверенность: падает — сеть «решилась»; упала почти до нуля, а побед мало — застряла).

Итог: `assets/ai/<name>.json` — веса для игры (в git не идут); `ai_runs/<name>/` — журнал и контрольная точка для `--resume`. Сыграть против него: «Настройки → Бот: ИИ <name>», потом «Тест с ботом» (или разминка в лобби).

Важно: правила с тех пор сильно менялись (жизни и урон ×2, снаряжение, пули, мобы) — старые сети (`fire-v2`) учились на старых правилах; учить заново с новым `--name`, а не `--resume` старых. После каждого заметного патча баланса сеть стоит доучивать (`--resume`) — коротко, если изменение небольшое.
