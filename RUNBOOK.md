# Spellgunners — ранбук

## Запуск

```bash
cd ~/projects/fast-game
.venv/bin/python main.py
```

Если установлен uv: `uv run main.py`.

Игра открывается на весь экран. F11 переключает окно / полный экран, F5 перечитывает картинки с диска, Esc в меню — выход.

## Первая установка (на новой машине)

Нужен только если папки `.venv` нет.

```bash
cd ~/projects/fast-game
python3 -m venv .venv
.venv/bin/pip install pygame pytest pyflakes
```

pytest и pyflakes нужны только для проверок (см. ниже), для игры хватает pygame.

## Установка на другие компьютеры (готовые сборки)

Готовая сборка — один файл, внутри всё: Python, pygame, картинки, звуки, шрифты. Ставить заранее ничего не нужно. Сборки лежат на странице выпуска на GitHub (Releases), как они туда попадают — в «Выпуск версии».

**Windows** — скачать `spellgunners-setup.exe` и запустить:

- Windows покажет «Система Windows защитила ваш компьютер» (SmartScreen: сборка не подписана платным сертификатом) → «Подробнее» → «Выполнить в любом случае».
- Установщик спросит про ярлык на рабочем столе; права администратора не нужны. Игра появится в «Пуск» как «Spellgunners», удалить — «Параметры» → «Приложения».
- При первой сетевой игре брандмауэр спросит разрешение — разрешить для **частных** сетей.
- Без установки: `spellgunners-windows.exe` — тот же файл игры, просто запустить.
- Настройки — в `%APPDATA%\duel`, при обновлении сохраняются.

**Linux** — скачать `spellgunners-linux.tar.gz`, в терминале:

```bash
tar xf spellgunners-linux.tar.gz
sh spellgunners/install.sh              # в меню приложений и ~/.local/bin/spellgunners, без sudo
sh spellgunners/install.sh --uninstall  # удалить (настройки в ~/.config/duel остаются)
```

Можно и без установки: `./spellgunners/spellgunners-linux`. Обновление — то же самое с новым архивом.

Проверить сборку без окна: `spellgunners-linux --selftest` (или `spellgunners-windows.exe --selftest`) — проиграет несколько секунд и сетевую игру с ботом, код выхода 0 — всё в порядке.

## Выпуск версии (GitHub)

Один раз — создать на GitHub пустой репозиторий с любым именем (например, `vibegame`; без README и .gitignore) и отправить туда код:

```bash
git remote add origin git@github.com:ИМЯ/РЕПОЗИТОРИЙ.git
git push -u origin master
```

Выпуск — метка версии (номер поднять и в `pyproject.toml`):

```bash

git push origin v0.2.0
```

GitHub сам (`.github/workflows/release.yml`, 5–10 минут) прогонит тесты, соберёт Linux и Windows, проверит обе сборки `--selftest` и выложит на страницу выпуска `v0.2.0`: `spellgunners-setup.exe`, `spellgunners-windows.exe`, `spellgunners-linux.tar.gz`, `spellgunners-linux`, `install.sh`. Ход сборки — вкладка Actions. Собрать без выпуска — Actions → «Сборка и выпуск» → Run workflow (файлы — в результатах запуска).

**Собрать на этом ноутбуке** (только Linux; Windows-сборку собирает GitHub):

## Поле

Левая половина поля — земля левого игрока, правая — правого (вид земли — по герою). В центре — **круглая арена мобов** (обсидиан, радиус 150 px, кромка наполовину цветом каждого героя): мобы появляются в ней, маги в неё не заходят. **Сверху и снизу от арены** можно пройти на землю соперника — но там отнимается `FOE_LAND_DPS` = 2 жизни в секунду (щит не спасает); зато там можно подобрать его артефакты и патроны. Ближний удар бьёт и соперника (2 жизни, щит гасит) и его двойников. Стреляют по прицелу (см. «Управление»). Артефакт выпадает, только если моб добит на твоей земле вне арены; пачки патронов падают на твоей земле вне арены. Размер арены — `ARENA_R` в `duel/config.py`.

Статус (верхняя полоса): у края — имя и жизни, под ними патроны и всё, что действует, с таймерами; ближе к центру — ячейки инвентаря и очередь; в самом центре — таймер волн мобов.

## Меню

| Пункт | Что это |
|---|---|
| 1. Два игрока | двое за одним компьютером: сначала выбор героев, потом партия (левый против правого) |
| 2. Создать игру по сети | твой компьютер становится сервером, ты — синий (см. «Игра по сети») |
| 3. Подключиться к игре | ввести адрес компьютера, создавшего игру, ты — красный |
| 4. Тестовый режим | два игрока по 1000 жизней — чтобы спокойно пробовать артефакты (тоже с выбором героев) |
| 5. Артефакты | справка в 2 страницы (A/D или ←/→): артефакты со значками и описаниями, правила |
| 6. Настройки | язык: русский, English, suomi |

Игра — для двух живых игроков: за одним компьютером режима против компьютера нет. Бот бывает только в сетевой игре — на месте второго игрока.

Выбор: W/S, ↑/↓ или крестовина. Начать: Enter, Пробел, ✕ на геймпаде или цифра 1–6.

### Герои

**Артефакты героев** — выпадают только из мобов, добитых своим героем, но подобрать и применить может любой (справка, страницы 2–4):

- **Свет**: «Луч света» — длинный (260 px) летящий луч насквозь, отскакивает от верха и низа; «убрать пули соперника»; «сбиваешь пули»; «мир с мобами».
- **Холод**: «Ледяная тропа» — 8 с чужая земля не жжёт, за магом ледяной след (земля Холода, тает за 6 с); «заморозить соперника»; «щит»; «пули соперника замирают» — 5 с его пули висят в воздухе (касаться больно), потом летят дальше.
- **Природа**: «Стена деревьев» — 750 px по прицелу на 8 с, сквозь неё не пройти никому, кроме самой Природы; «Медведь» — 10 с большой быстрый медведь с 20 жизнями, не стреляет, ближний удар дальше и сильнее; после — прежние жизни мага. «Дубовая кора» — 6 с снимает дебаффы, и артефакты соперника на Природу не действуют (урон — действует); «Лесные стражи» — 3 дерева-стрелка на земле соперника на 10 с, бьют его в пределах 260 px, по 3 жизни.
- **Огонь**: «Огненное лассо» — 3 с тянет соперника, не вырваться; «Огненный круг» — кольцо 95 px вокруг соперника на 6 с: стену не пересечь, у стены 4 жизни в секунду, пули изнутри гаснут; «быстрые пули»; «скорострельность».
- **Тьма**: «Восставшие мертвецы» — до 2 мобов рядом становятся зомби на 20 с, держатся не дальше 200 px от Тьмы и принимают её урон; «перевод стрелок»; «двойники» — не отличить от мага, бродят, по 2 жизни, подбирают артефакты хозяину; «стена-зеркало».

Числа — `BEAM_*`, `ICE_*`, `TREE_*`, `LASSO_SPEED`, `ZOMBIE_*`, `BEAR_*`, `FIRE_RING_*`, `CLONE_*`, `SENTRY_*`, `HERO_FADE` и `DURATION` в `duel/config.py`; кому что выпадает — `HERO_ONLY_ITEMS`.

Пять героев: **Огонь** (красный, земля — лава), **Холод** (белый, лёд), **Природа** (зелёный, трава), **Тьма** (чёрный с фиолетовым, пепел), **Свет** (жёлтый, золотой камень). Пока они отличаются только видом — правила у всех одинаковые (специализации — позже). Цвет пуль, подписей и земли — по герою.

Экран выбора перед партией за одним компьютером: верхняя строка — левый игрок (A/D — листать, Пробел — выбрать), нижняя — правый (←/→, Enter); геймпады — крестовина и ✕, ○ — передумать; Esc — в меню. Одного героя вдвоём взять нельзя: на героя, которого уже выбрал соперник, можно встать, но выбрать — нет. Выбор запоминается до выхода из игры. В сетевом лобби герой меняется ←/→ (A/D, крестовина) на своей карточке; бот берёт свободного.

Как добавить героя: строка в `HEROES` и словарях `HERO_*` в `duel/config.py` (цвет, раскраска мага `MAGE_*_PALETTE`, фон), фон — в `tools/make_sprites.py`, название — `hero.*` в `duel/i18n.py`.
Из справки назад: Esc, Enter, Пробел, ✕ или ○.

Если жизней больше 5, в панели рисуется 5 сердечек и «+остаток»: например, `♥♥♥♥♥ +5` — это 10 жизней.

## Настройки и языки

Пункт меню «Настройки»:

- **Язык** — русский, English, suomi. Выбор строки: W/S или ↑/↓, изменить: A/D, ←/→ или Enter (на геймпаде — крестовина и ✕), назад: Esc или ○. Меняется сразу.
- **Прицел стиком** (1–10, по умолчанию 6) — как быстро прицел поворачивается за правым стиком; 10 — сразу, 1 — медленно и точно. **Прицел мышью** (1–10, по умолчанию 5) — скорость перекрестия: 1 — в 5 раз медленнее мыши, 5 — как мышь, 10 — вдвое быстрее. Меняются A/D или ←/→.
- **Имя** — как тебя видят в сетевой игре (панель сверху, экран победы, список игр у других). Набирается на любом языке, до 16 символов; пока выбрана эта строка, буквы (и W/S) идут в имя, строки листаются стрелками ↑/↓, Backspace стирает. Пустое имя — «Синий»/«Красный», как раньше. За одним компьютером (хотсит) игроки всегда называются по цвету.

Всё запоминается между запусками в `~/.config/duel/settings.json` (Windows — `%APPDATA%\duel\settings.json`).

Все тексты игры — в `duel/i18n.py`, по словарю на язык. Новый текст добавляется во все три словаря с одинаковым ключом; тест проверяет, что ни один ключ не пропущен и числа (`{n}` и т. п.) везде одни и те же. Новый язык — ещё один словарь и строка в `LANGS`.

## Управление

| | Клавиатура и мышь (левый игрок) | Геймпад |
|---|---|---|
| Движение (в любую сторону) | W / A / S / D | левый стик или крестовина |
| **Прицел** (в любую сторону) | мышь | правый стик |
| Выстрел | левая кнопка мыши или Пробел | R1 или R2 |
| Ближний удар (только по мобам) | правая кнопка мыши или E | L1 или L2 |
| Артефакты, ячейки 1–4 | 1 2 3 4 | □ △ ○ ✕ |
| В меню | Esc | Options |
| После победы: ещё раз | R | ✕ |

**Режим прицела** (в «Настройках», строка «Прицел»): **«по движению»** — по умолчанию, проба: прицел туда, куда идёт маг, стоит — прямо на соперника; стик и мышь не целятся, геймпад за одним компьютером не обязателен. **«стик и мышь»** — всё, что ниже.

**Мышь в партии** двигает своё перекрестие на поле (системный курсор спрятан и не уходит из окна; в меню, лобби, на экране победы и при переключении окна — обычный курсор). **Правый стик** поворачивает прицел плавно; прицел меняется, только когда стик отклонён уверенно, — при отпускании не дёргается. Скорость того и другого — в «Настройках».

**Прицел** — это направление: пуля летит туда, куда смотрит стрелка рядом с магом, — хоть назад, хоть вверх, пока в кого-нибудь не попадёт (от верхнего и нижнего края отскакивает). Бег на направление выстрела не влияет. Маг поворачивается лицом к прицелу. Веер — три пули вокруг прицела.

**За одним компьютером нужен хотя бы один геймпад** (одному из двоих целиться нечем):

- **один геймпад** — левый игрок: клавиатура и мышь, правый: геймпад;
- **два геймпада** — первый у левого, второй у правого (мышь не участвует);
- без геймпада экран выбора героев напишет «нужен хотя бы один геймпад» и партию не начнёт.

Клавиши правого игрока остались (стрелки — ход, Enter — выстрел, правый Shift — удар, 9 0 - = — ячейки), но целиться ими нельзя — выстрел по прямой. По сети свой маг — клавиатура и мышь или свой геймпад. Клавиши работают в любой раскладке.

## Геймпады

Оба геймпада подключаются по USB-проводу, ничего настраивать не нужно.

- **Один геймпад — у правого игрока** (левый играет клавиатурой и мышью). **Два — первый у левого, второй у правого.** Чтобы поменять, переподключите их в нужном порядке.
- Правый стик — прицел.
- Внизу меню написано, какие геймпады найдены и кто за кого играет.
- У игрока с геймпадом ячейки инвентаря стоят ромбом, как кнопки: △ сверху, □ слева, ○ справа, ✕ снизу. С клавиатуры — в ряд 1–4.

Можно и по Bluetooth: беспроводной PS4-геймпад уже сопряжён, достаточно нажать на нём кнопку **PS**.

### Если геймпад не работает

1. Проверить, видит ли его система:
   ```bash
   ls /dev/input/js*
   ```
   На каждый геймпад должно быть устройство `js0`, `js1`.
2. Не видит → переподключить кабель, попробовать другой USB-порт.
3. Bluetooth не подключается → зажать **Share + PS** (на DualSense: **Create + PS**), пока подсветка не замигает часто, затем в «Настройки → Bluetooth» удалить «Wireless Controller» и выбрать его заново.
4. Геймпад подключили, когда игра уже запущена — игра подхватит его сама. Если нет, перезапустить игру.

## Ближний удар

- Кнопка: E у синего, правый Shift у красного, на геймпаде L1 или L2 (L2 — один удар на нажатие).
- Бьёт **только мобов**: всех, чей край не дальше 30 px от края мага, в любую сторону. Мага-соперника, двойников, пули и снаряды не задевает.
- 2 урона каждому, раз в 0,6 с, патроны не тратит; работает и под заморозкой, «не стреляет», запретом артефактов.
- Задетый моб злится на ударившего; убитый ударом — по общему правилу: артефакт выпадает, только если моб погиб на земле ударившего.
- Взмах виден кольцом вокруг мага, звук — `assets/sounds/shoot03.mp3`.
- Настройки — `MELEE_DAMAGE`, `MELEE_RANGE`, `MELEE_COOLDOWN` в `duel/config.py`.

## Патроны

- В начале партии у каждого 20 патронов, верхнего лимита нет.
- Каждый выстрел тратит 1 патрон, веер из трёх пуль — тоже 1. Двойники стреляют бесплатно.
- Пачки по 20 патронов появляются в случайном месте земли игрока в среднем раз в 13 с (≈90 патронов в минуту) и лежат 10 с.
- Пачка подбирается сразу, в инвентарь не идёт — подбирается даже при полном инвентаре.
- Патроны кончились — счётчик в панели красный, при попытке выстрела всплывает «нет патронов».

## Мобы

- Мобы (обсидиановые големы) приходят **волнами**. Первая — сразу в начале партии, дальше каждые 15 с.
- Каждый моб появляется в **случайном месте полосы мобов** — фиолетовой обсидиановой полосы посередине поля (40–60% ширины, `MOB_ZONE`). Заранее прицелиться нельзя.
- Первая волна — 4 моба по 3 жизни. В каждой следующей на 1 моба и на 1 жизнь больше. **Уже живые мобы при новой волне не меняются** — раненые не лечатся.
- **Ограничения:** на поле не больше 8 мобов, у моба не больше 6 жизней.
- Когда волна дошла до максимума (8 мобов по 6 жизней), каждая следующая приходит **на секунду раньше**: 15 → 14 → … → 3 с между волнами.
- **Таймер волн** — в центре статуса, между инвентарями: номер волны и секунды до следующей.
- Пока их не трогают, мобы стоят на месте и ловят пули обоих игроков.
- Попал в моба — он идёт на тебя и встаёт прямо перед тобой (так его всегда можно достать прямым выстрелом). Если потом попал соперник — разворачивается на соперника.
- Дошёл — бьёт: −1 жизнь раз в секунду. Щит гасит удар моба так же, как пулю (тратит одно «попадание» щита).
- «Пули соперника медленнее» замедляет и мобов, которые идут на тебя; «быстрые пули» ускоряет мобов, которые идут на соперника. Множители — `SLOW_BULLET_FACTOR`, `FAST_BULLET_FACTOR`.
- **Дальнобойные мобы** — каждый третий моб волны (в первой волне — один из четырёх). Выглядят иначе: замшелые зелёные, с ядовитым кристаллом на голове. Разозлившись, не идут вплотную, а подходят на ~220 px и раз в 1,5 с стреляют зелёными снарядами. Стреляют, только если цель не дальше 280 px; снаряд пролетает не больше 280 px и исчезает. Снаряд снимает 1 жизнь, щит его гасит; замедление и «быстрые пули» действуют на снаряды так же, как на движение мобов; стены-зеркала и «сбиваешь пули» на них не действуют. Настройки — `MOB_RANGED_EVERY`, `MOB_RANGE`, `MOB_KEEP_DISTANCE`, `MOB_SHOT_SPEED`, `MOB_SHOT_COOLDOWN`.
- Над мобом — полоска жизней и число; цвет показывает, на кого он идёт (серый — ни на кого).
- Настройки — `MOB_*` в `duel/config.py`: `MOB_EVERY`, `MOB_EVERY_MIN`, `MOB_SPEEDUP`, `MOB_COUNT`, `MOB_HP`, `MOB_MAX`, `MOB_MAX_HP`, `MOB_AREA`.

## Артефакты

Полное описание с значками — в игре, пункт меню «Артефакты».

- **Артефакты выпадают только из убитых мобов — и только если моб погиб на земле того, кто его добил.** Добил моба на полосе мобов или на чужой земле — ничего не выпало. Значит, моба надо заманить на свою землю (разозлённый моб сам идёт на того, кто в него попал) и добить там.
- Артефакт падает **ровно на месте гибели** моба и **лежит, пока маг сам не подберёт** его — по времени не исчезает.
- Подобранный артефакт ложится в свободную ячейку (их 4), а если все заняты — **в очередь** (без ограничения). Освободилась ячейка — в неё сразу встаёт первый из очереди. 3 следующих видно в ряд (с клавиатурой — под ячейками, с геймпадом — рядом с ромбом), «+N» — если в очереди больше.
- Лечение срабатывает сразу при подборе, минуя ячейки.
- **Улучшения оружия** (веер, волна, скорострельность, сбивание пуль) — тоже через ячейки, держатся 6 с (`WEAPON_TIME`). Разных одновременно не больше трёх (`WEAPON_MAX`): новое вытесняет то, у которого меньше всего времени.
- **Всё стакается:** повтор любого эффекта добавляет ему время; два щита подряд — вдвое больше и времени, и ударов; повторные двойники — новые до лимита (4) и ещё 15 с жизни живущим; стен может стоять несколько.
- **Статус:** всё, что сейчас действует на игрока, показано значками с таймерами во второй строке под его именем (оружие первым): щит — «удары×секунды», стены — «кол-во×секунды», двойники — «×кол-во». На поле — только кольца вокруг мага.
- Рамка: зелёная — защита, синяя — атака, оранжевая — бьёт по сопернику.
- Разные эффекты действуют вместе (заморозка + «не стреляет», волна + веер + скорость).
- Дебаффы соперника снимаются только временем или очищением.
- На двойников переходят эффекты хозяина: щит, все улучшения оружия, ×2, уменьшение, скорость, «не стреляет».

### Матч и приложение

Игра разделена на две части (так проще будет играть по сети — см. «Сетевая версия»):

- **Матч** (`duel/match.py`, класс `Match`) — правила и состояние одной партии. Ничего не знает про окно, звук, клавиши и язык. Один шаг: `events = match.step(1/60, {"blue": Command(...), "red": Command(...)})` — получает команды игроков, возвращает события: `("shot", "blue")`, `("pickup", "red", "shield")`, `("used", кому, артефакт)`, `("ammo", кто, 20)`, `("no_ammo", кто)`, `("melee", кто)`, `("mob_dead", x, y)`, `("wave", номер, мобов, жизней)`.
- **Приложение** (`duel/game.py`, класс `Game`) — окно, меню, настройки. Клавиатуру и геймпады превращает в команды, делает шаги матча ровно 60 раз в секунду (такт фиксированный, от скорости кадров не зависит), события превращает в звук и всплывающие надписи на языке игрока. Новая партия — новый `Match`. Рисует `screens.py`, читая `game.match`.
- **Случайность** — только из генератора матча `match.rng` (зерно: `Match(seed=...)`). Одно зерно и те же команды → та же партия. Общий `random` в правилах не использовать.
- **Номера объектов**: у мобов, пуль, снарядов, артефактов, пачек, стен, двойников — `id` из счётчика матча (выдаётся в конце шага); маги — `"blue"` / `"red"`.
- **Снимок** (`duel/snapshot.py`): `snapshot(match)` — словарь из чисел, строк, списков: маги (место, размер, жизни, патроны, эффекты с таймерами, ячейки, очередь), пули, мобы, снаряды, артефакты, пачки, стены, двойники, волна, победитель. Приложение берёт снимок после каждого такта (`game.snap`), и **экран рисует только по нему** — так же будет рисовать клиент в сети. Матч, сущности и снимок не загружают pygame.

Как добавлять механику: **правило — в матч** (`match.py`, сущности — `entities.py`), **вид и звук — в приложение**. Если новое надо видеть на поле: поле в снимке (`snapshot.py`) → рисование по снимку (`render.py`, строка в `draw_field`) или в статусе (`screens.py`). Если игроку надо что-то показать или проиграть звук — матч делает `self.emit("ключ", ...)`, а `Game.handle_events` решает, как это показать. Текст и цвет в матч не попадают.

Новый артефакт: строка в `ITEMS` и `HELP_SECTIONS` и описание в `item_help` (`duel/items.py`), значок в `duel/icons.py`, действие в `Match.apply_item` (`duel/match.py`).

Тесты правил работают на фикстуре `match` (матч без окна, шаги — `step(match, секунды, moves={"blue": (0, -1)})`), тесты меню, ввода и отрисовки — на фикстуре `game`.

**Отпечаток партии** (`tools/fingerprint.py`): партии двух случайных ботов с фиксированными зёрнами, хеш состояния каждую секунду. Тест сравнивает его с `tests/data/fingerprint.json` — так видно, что перестройка кода не поменяла поведение. Если правила или баланс меняются **намеренно**, эталон перезаписать:

```bash
.venv/bin/python tools/fingerprint.py --save tests/data/fingerprint.json
```

## Разработка по спецификациям (OpenSpec)

В проекте подключён [OpenSpec](https://github.com/Fission-AI/OpenSpec) — spec-driven development: сначала спецификация изменения, потом код.

- CLI: `openspec` (стоит в `~/.local/bin`, версия 2.1). Обновить: `npm install -g --prefix ~/.local @fission-ai/openspec@latest`, потом `openspec update` в проекте.
- Папки: `openspec/specs/` — текущие спецификации игры, `openspec/changes/` — предлагаемые изменения, `openspec/changes/archive/` — завершённые. `openspec/config.yaml` — контекст проекта и правила (язык артефактов — русский).
- Скиллы для Claude Code лежат в `.agents/skills/` (ссылки — в `.claude/skills/`).
- Текущая игра описана в `openspec/specs/` (12 разделов): `battlefield` (поле и движение), `shooting` (стрельба, жизни, победа), `ammo`, `artifacts` (выпадение, инвентарь, очередь, стаки), `artifact-effects` (что делает каждый артефакт), `mobs`, `melee` (ближний удар), `controls`, `menus`, `settings` (языки), `hud` (статус), `audio-graphics`. Проверка формата: `openspec validate --specs --strict`.

Порядок работы в Claude Code:

1. `/openspec-propose <что хотим>` — создаёт `openspec/changes/<имя>/`: `proposal.md` (что и зачем), `specs/…` (что должна делать игра — дельта к спецификации), `design.md` (как), `tasks.md` (шаги). Код при этом не трогается.
2. Прочитать, поправить, обсудить.
3. `/openspec-apply-change` — реализация по `tasks.md`.
4. `/openspec-archive-change` — изменение вливается в `openspec/specs/`, папка уходит в архив.

Ещё: `/openspec-explore` — обдумать идею без изменений в файлах. Полезные команды: `openspec list` (изменения), `openspec list --specs`, `openspec view` (дашборд).

Телеметрия OpenSpec отключена: `openspec config set telemetry.enabled false`.

## Игра по сети

Два компьютера в одной сети (дома — один Wi-Fi) или два окна на одном компьютере. Компьютер, создавший игру, — сервер: матч считается на нём, второй получает картинку и шлёт свои нажатия.

**Из меню:**

1. Первый игрок: «Создать игру по сети». На экране — адрес этого компьютера, например `192.168.1.5`. Пока второго нет, B (△) — играть с ботом, Esc (○) — отмена.
2. Второй игрок: «Подключиться к игре». Игра сама ищет созданные игры в сети и показывает список: имя создателя (из его настроек, а если не задано — имя компьютера), адрес, «ждёт второго игрока» / «мест нет» / «другая версия игры». Первая найденная игра выбирается сама — сразу Enter (✕); другую — стрелками ↑/↓ или крестовиной. Если в списке пусто — набрать адрес вручную в нижней строке (цифры, точки; любая раскладка); последний удачный адрес запоминается.
3. **Лобби.** Оба видят два места — кто сел и кто готов. Enter, Пробел или ✕ — «готов» (ещё раз — «не готов»). Партия начинается, когда готовы оба. У создателя в лобби — адрес компьютера и B (△) — посадить бота на свободное место и сразу начать. Создатель — синий, гость — красный; сверху — имена из настроек (место бота — «Бот»). Управление — как обычно, любой раскладкой или своим геймпадом.
4. **Реванш.** После победы R (✕) — «хочу реванш»; новая партия, когда нажали оба (видно, кто уже нажал).
5. **Выход.** Esc (Options) — в меню, место сразу свободно; соперник возвращается в лобби ждать нового. Если вышел создатель, у гостя — «Создатель игры вышел».
6. **Обрыв связи.** Если у кого-то пропал Wi-Fi (или 3 секунды нет связи), партия встаёт на паузу — у соперника надпись «…: связь потеряна — ждём N с». Отключившийся сам переподключается раз в секунду и возвращается на своё место, партия продолжается с того же момента. Не вернулся за 30 секунд — место освобождается, соперник — в лобби.

Картинка у обоих идёт с задержкой около 0,1 секунды и плавно — так незаметны неровности Wi-Fi.

**Если не подключается:**

- «на этом адресе игра не создана» — на том компьютере не нажали «Создать игру» или адрес набран с ошибкой;
- «компьютер не отвечает» или игра не появляется в списке — компьютеры в разных сетях, или брандмауэр. Linux с `ufw` на компьютере с игрой: `sudo ufw allow 5555/tcp` и `sudo ufw allow 5556/udp` (5556 — поиск игр). Windows при первом запуске спрашивает разрешение — разрешить для **частных** сетей; если отказали — «Брандмауэр Защитника Windows» → «Разрешить взаимодействие с приложением» → отметить игру;
- игра не появляется в списке, но по адресу подключается — сеть (например, раздача с телефона) не пропускает широковещательные пакеты: вводить адрес вручную;
- «в игре уже два игрока»; «другая версия игры» — обновить игру на обоих компьютерах (`git pull`);
- «Не удалось создать игру: порт 5555 занят» — уже запущена другая игра или сервер; закрыть её.

**Два окна на одном компьютере** (проверить сеть одному или играть с двумя геймпадами): запустить игру из терминала дважды в окне — `.venv/bin/python main.py --windowed` и `.venv/bin/python main.py --windowed --pad 1`. В первом окне «Создать игру», во втором «Подключиться» к `localhost`. Клавиатура достаётся окну в фокусе, а геймпад клиента работает и без фокуса (`--pad N` — номер своего геймпада, с 0).

**Сервер без окна** (например, на отдельном компьютере):

```bash
.venv/bin/python -m duel.server            # ждёт двух игроков на порту 5555
.venv/bin/python -m duel.server --bot      # пустое место — бот
.venv/bin/python -m duel.server --port 6000
.venv/bin/python main.py --connect 192.168.1.5 --windowed   # подключиться из терминала
```

Как устроено: поиск — UDP-вопрос «кто создал игру?» на порт 5556 всей сети, сервер отвечает именем и портом (`duel/discovery.py`); протокол игры — TCP, сообщения JSON по одному в строке, версия 3: место по запросу с ключом для возврата, лобби и готовность (`duel/net.py`); сервер шагает матч 60 раз в секунду и шлёт снимок 30 раз в секунду (`duel/server.py`); клиент сглаживает движение между снимками (`duel/interp.py`). План дальнейших этапов (лобби, переподключение, зрители, портал) — в [`docs/network-roadmap.md`](docs/network-roadmap.md).

| `bg_ice.png` | земля синего, лёд | 125×160, игра увеличивает в 4 раза |
| `bg_lava.png` | земля красного, лава | 125×160, игра увеличивает в 4 раза |
| `bg_mob.png` | полоса мобов посередине, обсидиан | 50×160, игра увеличивает в 4 раза |
| `mob.png` | моб (обсидиановый голем), смотрит вправо | 16×16, прозрачный фон |
| `mob_ranged.png` | дальнобойный моб (зелёный, с кристаллом), смотрит вправо | 16×16, прозрачный фон |

**Маг рисуется один раз.** Красного игра делает из `mage.png` сама: заменяет четыре цвета команды и зеркалит. Поэтому любая правка рисунка сразу попадает в обоих. Цвета команды (заменяются у красного):

| На рисунке (синий) | У красного | Где |
|---|---|---|
| `#b9d4f0` | `#dc3c32` | мантия и шляпа |
| `#6e96cd` | `#8c1e23` | тень |
| `#f0f8ff` | `#ff8c64` | блик |
| `#78e1ff` | `#ffd646` | кристалл на шляпе → звезда |

Чтобы деталь была цвета команды — рисуйте её одним из этих четырёх цветов. Любой другой цвет будет у обоих магов одинаковым. Таблица замены — `MAGE_RED_PALETTE` в `duel/config.py`.

**Порядок работы:**

1. Поставить редактор (один раз): `sudo snap install pixelorama`. Подойдут и LibreSprite, Aseprite.
2. Запустить игру в окне (F11) и открыть PNG в редакторе рядом.
3. Нарисовать, сохранить PNG (тот же размер, формат PNG, прозрачный фон у мага).
4. В игре нажать **F5** — картинки перечитаются с диска, изменения видны сразу.

Новый размер мага (например 48×48) тоже можно — игра масштабирует его под круг попадания. Попадания считаются по кругу, не по картинке; насколько картинка больше круга — `SPRITE_TO_HITBOX` в `duel/sprites.py`.

**Скрипт `tools/make_sprites.py`** создаёт начальные версии картинок. Существующие файлы он не трогает:

```bash
.venv/bin/python tools/make_sprites.py                       # дорисовать недостающие PNG
.venv/bin/python tools/make_sprites.py --preview /tmp/p.png  # крупный предпросмотр обоих магов на фонах
.venv/bin/python tools/make_sprites.py --force               # перерисовать всё с нуля — ваши правки пропадут!
```
