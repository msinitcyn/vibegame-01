# distribution Specification

## Purpose
Готовые сборки игры для Linux и Windows: один файл со всем внутри, установщик Windows с ярлыками, установка в меню приложений на Linux, выпуск версий на GitHub.

## Requirements

### Requirement: Сборки без предустановки
Для Linux и Windows SHALL быть готовые сборки игры, внутри которых всё нужное для запуска: Python, библиотеки, картинки, звуки, музыка и шрифты. Запуск сборки MUST NOT требовать установленного Python, pygame или других пакетов.

#### Scenario: Чистый Windows
- **WHEN** на компьютере с Windows без Python запускают `spellgunners-windows.exe`
- **THEN** открывается игра со звуком, музыкой и картинками

#### Scenario: Linux без окружения
- **WHEN** на Ubuntu без окружения Python игры запускают `spellgunners-linux`
- **THEN** открывается игра

### Requirement: Установщик Windows
Для Windows SHALL быть установщик `spellgunners-setup.exe`, который без прав администратора ставит игру в папку пользователя, создаёт ярлыки в меню «Пуск» и (по выбору) на рабочем столе и регистрирует удаление в списке программ.

#### Scenario: Установка и ярлык
- **WHEN** ребёнок запускает `spellgunners-setup.exe` и проходит шаги установки
- **THEN** в меню «Пуск» появляется «Spellgunners» со значком, и игра запускается с ярлыка

### Requirement: Установка на Linux
Рядом с Linux-сборкой SHALL лежать скрипт установки, который кладёт игру в `~/.local/bin` и добавляет её в меню приложений со значком, без прав администратора.

#### Scenario: Меню приложений
- **WHEN** пользователь запускает `install.sh`
- **THEN** «Spellgunners» появляется в меню приложений и запускается оттуда

### Requirement: Шрифты и значки в любой системе
Игра SHALL брать шрифты из своих файлов, а не из системы, так что русские и финские буквы и значки интерфейса (♥, ✕, △, ○, ◀, ▶) MUST отображаться одинаково на Linux и Windows. У окна и ярлыков MUST быть значок игры.

#### Scenario: Windows без DejaVu
- **WHEN** игру запускают на Windows, где нет шрифта DejaVu Sans
- **THEN** меню и статус показывают кириллицу и значки кнопок геймпада правильно

### Requirement: Настройки в папке пользователя
Настройки SHALL храниться в папке пользователя, принятой в системе: на Windows — `%APPDATA%\duel`, на Linux — `~/.config/duel`. Переустановка или обновление игры MUST NOT сбрасывать настройки.

#### Scenario: Обновление
- **WHEN** на Windows ставят новую версию игры поверх старой
- **THEN** выбранный язык и последний адрес сервера сохраняются

### Requirement: Выпуск версии
Публикация версии (метка `v*` в репозитории на GitHub) SHALL автоматически собирать Linux-сборку, Windows-сборку и установщик и прикладывать их к странице выпуска. Сборка MUST начинаться только после зелёных проверок — тех же, что на каждый push (тесты и самопроверка на Linux и Windows, строгая проверка спецификаций), — и если метка совпадает с версией в `pyproject.toml`; иначе выпуска нет.

#### Scenario: Новая версия
- **WHEN** в репозиторий на GitHub отправлена метка `v0.2.0`
- **THEN** на странице выпуска `v0.2.0` появляются `spellgunners-linux.tar.gz`, `spellgunners-linux`, `install.sh`, `spellgunners-windows.exe` и `spellgunners-setup.exe`

#### Scenario: Метка не та
- **WHEN** отправлена метка `v0.8.0`, а в `pyproject.toml` версия 0.7.4
- **THEN** сборка не начинается, в журнале — что сначала нужен коммит «Версия 0.8.0»

#### Scenario: Красный CI
- **WHEN** отправлена метка `v0.8.2`, а тест на Windows падает
- **THEN** сборка не начинается, страницы выпуска `v0.8.2` нет

### Requirement: Одна копия игры
Игра SHALL запускаться на компьютере в одной копии: вторая копия MUST сообщать «Spellgunners уже запущен» (на Windows — окном) и закрываться. Переменная окружения `DUEL_MULTI=1` разрешает несколько копий (для проверки сети на одном компьютере); самопроверка `--selftest` не ограничивается.

#### Scenario: Двойной щелчок по ярлыку
- **WHEN** игра открыта, и игрок ещё раз запускает её с ярлыка
- **THEN** появляется сообщение «Spellgunners уже запущен», вторая копия не открывается

### Requirement: Логи и файлы падений
Игра SHALL вести лог в папке `logs` рядом с настройками: запуск (версия, система), партии, применённые артефакты, команды чата, вход в сеть и выход из неё; лог MUST NOT расти бесконечно (не больше 3 файлов по 1 МБ). При падении игра MUST записывать полный текст ошибки с версией в отдельный файл `crash-<дата>.txt`; собранная игра на Windows MUST показывать окно с путём к этому файлу.

#### Scenario: Игра упала
- **WHEN** во время партии случилась ошибка и игра закрылась
- **THEN** в `logs` есть `crash-…txt` с версией игры и текстом ошибки, а в `game.log` видно, какие артефакты применяли перед этим

### Requirement: Проверки на каждый push
Каждый push в master и каждый pull request SHALL запускать проверки: pyflakes, тесты и самопроверку из исходников на Linux и Windows, строгую проверку спецификаций OpenSpec. Падение на любой из систем MUST делать проверку красной.

#### Scenario: Сломанный тест
- **WHEN** в master отправлен коммит, после которого падает тест
- **THEN** у коммита на GitHub красный значок проверки «Проверки»

#### Scenario: Сломалось только на Windows
- **WHEN** после коммита тест падает на Windows, а на Linux проходит
- **THEN** у коммита красный значок проверки «Проверки»

### Requirement: Статистика партий
Итог каждой законченной партии SHALL записываться строкой JSON в `matches.jsonl` (игра — в свои логи для партий за этим компьютером, сервер — в свои для сетевых): режим, герои, победитель, длительность, волна, жизни, снаряжение, что каждый маг подобрал и применил, выстрелы, полученный урон, зерно, версия. `tools/balance.py` SHALL показывать по этим файлам процент побед героев и пар героев и статистику артефактов; тест с ботом и разминка MUST по умолчанию не входить в сводку.

#### Scenario: Сводка
- **WHEN** сыграно 20 партий и запущен `tools/balance.py`
- **THEN** видно, сколько побед у каждого героя и как часто побеждает тот, кто применил каждый артефакт

### Requirement: Повтор партии
Каждая законченная партия SHALL записываться в `replays/` папки логов (игра — партии за этим компьютером, сервер — свои; хранятся последние 50): начало партии, команды игроков по тактам и тестовые команды. Прогон записи MUST давать ту же партию (те же позиции, жизни, победителя). `python main.py --replay ФАЙЛ` SHALL показывать повтор в окне игры с паузой, скоростью, перемоткой вперёд и началом заново; `python -m duel.replay ФАЙЛ` — проверять запись без окна.

#### Scenario: Посмотреть партию
- **WHEN** партия закончилась, и игрок запустил `python main.py --replay` с её файлом
- **THEN** партия идёт заново так же, как была, с тем же победителем

#### Scenario: Ошибка в комнате
- **WHEN** в комнате сервера случилась ошибка
- **THEN** рядом с файлом ошибки лежит повтор партии до ошибки

### Requirement: Отчёты о падениях
Игра SHALL отправлять отчёты о падениях серверу, к которому подключается, только с разрешения игрока: после падения при следующем запуске MUST спрашиваться разрешение (ответ запоминается и меняется в настройках). В отчёте MUST NOT быть пути к домашней папке и имени пользователя; каждый отчёт MUST уходить один раз. Сервер SHALL сохранять отчёты в `client-crashes/` папки логов, принимая не больше 3 с одного соединения.

#### Scenario: Разрешил
- **WHEN** игра упала, при следующем запуске игрок нажал «Да, отправлять» и подключился к серверу
- **THEN** на сервере в `client-crashes/` появляется отчёт с версией и текстом ошибки, без имени пользователя и путей

#### Scenario: Не разрешил
- **WHEN** игрок ответил «Нет»
- **THEN** отчёты остаются только на его компьютере

### Requirement: Браузерная версия (проба)
Игру SHALL можно собрать для браузера (pygbag) из того же кода: `tools/build_web.py` и `python -m pygbag`. В браузере MUST работать игра за одним компьютером, тест с ботом, справка и настройки; игра по сети, свой сервер и автообновление в браузере MUST NOT быть доступны (понятное сообщение вместо сети). Компьютерная версия MUST вести себя как раньше.

#### Scenario: Открыть в браузере
- **WHEN** игрок открыл браузерную версию и выбрал «Тест с ботом»
- **THEN** партия идёт в браузере со звуком, а «Играть по сети» говорит, что в браузере пока без сети

#### Scenario: Без геймпадов
- **WHEN** браузерная версия запущена там, где у pygame нет модуля геймпадов
- **THEN** игра работает с клавиатурой и мышью, геймпадов в ней нет

### Requirement: Меню браузерной версии
В браузерной версии главное меню SHALL быть без кнопки «Выход»; пункт сети MUST называться «Подключиться к серверу»; версия — без проверки обновлений; в настройках MUST NOT быть прицела вдвоём, обновлений и отчётов о падениях.

#### Scenario: Меню в браузере
- **WHEN** игрок открыл браузерную версию
- **THEN** в меню нет «Выход», а вместо «Играть по сети» — «Подключиться к серверу»
