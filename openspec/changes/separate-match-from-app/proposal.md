# Proposal

## Why

Это этап 0 сетевой версии (см. `docs/network-roadmap.md`). Чтобы правила игры могли работать на сервере, а клиенты — только рисовать и читать ввод, правила нужно отделить от окна, звука, клавиатуры и меню. Сейчас всё это живёт в одном классе, и сервер без окна из него не сделать. Изменение затрагивает почти весь игровой код, поэтому делается первым и сразу в `main`, чтобы дальнейшие игровые изменения писались уже в новой структуре.

## What Changes

- Появляется **матч** — правила и состояние партии без окна, звука, событий pygame и меню. Один шаг матча получает команды игроков и фиксированный шаг времени и возвращает список событий.
- **Команды игроков** вместо клавиш: направление движения, выстрел, удар, ячейка инвентаря. Клавиатура и геймпады превращаются в команды в приложении; правила о клавишах больше не знают.
- **События** вместо прямых вызовов: выстрел, удар, подбор, применение артефакта, патроны, «нет патронов», гибель моба, новая волна. Звук, всплывающие надписи и их перевод на язык игрока делает приложение. Ограничение «нет патронов» не чаще раза в секунду считается по времени матча.
- **Фиксированный такт** 60 раз в секунду: приложение копит время кадров и делает нужное число шагов матча.
- **Свой генератор случайных чисел** у каждой партии (с зерном) — партию с одним и тем же зерном и командами можно повторить один в один.
- **Постоянные номера** у объектов поля (мобы, пули, снаряды, артефакты, пачки, стены, двойники) — понадобятся клиенту для сопоставления снимков.
- Приложение (окно, меню, настройки, ввод, звук, отрисовка) работает поверх матча; хотсит — это приложение с одним локальным матчем.
- Поведение игры для игрока **не меняется**: те же правила, управление, экраны, звуки и надписи.

## Impact

- Код: новый модуль матча и модуль команд; `game.py` становится приложением поверх матча; `screens.py` читает состояние из матча; `entities.py` берёт случайность из генератора матча и получает номера объектов; ввод (клавиатура, геймпад) превращается в команды.
- Тесты: правила проверяются на матче напрямую (без окна); тесты меню, ввода и отрисовки — на приложении. Новые тесты: матч без окна, повторяемость по зерну, совпадение «отпечатка» партии до и после перестройки.
- Документация: `RUNBOOK.md` (структура, как добавлять механику), `docs/network-roadmap.md` (этап 0 выполнен), контекст `openspec/config.yaml`.
