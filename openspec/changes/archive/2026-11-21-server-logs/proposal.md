## Why

Сервер пишет события через `print`, без времени и уровня, и только в консоль: после перезапуска история пропадает, а при ошибке в комнате остаётся одна трассировка, по которой партию не повторить. Это первый пункт плана инфраструктуры: логи — основа для разбора проблем по сети, метрик и повтора партий.

## What Changes

- `python -m duel.server` пишет в консоль и в `logs/server.log` (рядом с настройками или `--logs ПАПКА`; 5 файлов по 5 МБ): время, уровень (ошибки — ERROR), версия и система при запуске; падения потоков тоже записываются.
- Новые записи: итог партии (кто кого, герои, длительность, волна, жизни, зерно); раз в минуту боя — связь каждого игрока (пинг, снимков/с, джиттер, FPS).
- Ошибка в комнате пишет `room-error-<дата>-<комната>.json`: зерно, герои, такт, места, состояние магов и команды игроков за последние 5 с (300 тактов), текст ошибки.
- Свой сервер внутри игры пишет в `game.log` с пометкой `[сервер]`, файлы ошибок комнат — в `logs/`.
- CI: упавшие тесты выводятся ещё и аннотациями (плагин `pytest-github-actions-annotate-failures`), чтобы их было видно без входа на GitHub.
