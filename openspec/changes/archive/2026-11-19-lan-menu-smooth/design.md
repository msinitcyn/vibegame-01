# Design

## Context

После `lan-server-client` есть сервер без окна (`duel/server.py`, однопоточный `select`, такты 60 Гц, снимок и события каждый такт, протокол 1 — JSON по строкам), клиентский режим `Game` (`net_frame`: команды каждый такт, снимок рисуется сразу по приходу) и запуск только из терминала (`main.py --connect`). Сервер начинает партию с первым подключившимся. Снимок весит 1,2–1,6 КБ JSON (замерено на партии ботов), то есть 30 снимков в секунду — около 45 КБ/с: для Wi-Fi это немного.

## Goals / Non-Goals

**Goals:**
- Сетевая игра из меню: создать (сервер в той же программе) и подключиться (ввод адреса, запоминание).
- Партия начинается, когда заняты оба места.
- Гладкая картинка при неровном приходе снимков; звук и надписи — вместе с картинкой.
- Возврат в меню при Esc и при обрыве связи, с понятным сообщением.

**Non-Goals:**
- Лобби с «готов», имя игрока, переподключение к идущей партии, поиск игр в сети (этап 3).
- Предсказание своего мага (ввод → картинка без задержки), сжатие снимков, UDP (этап 6).
- Зрители (этап 4).

## Decisions

1. **«Создать игру» — тот же `Server` в фоновом потоке.** Поток выполняет `server.run()`; у сервера появляется `stop()` (флаг + закрытие слушающего сокета и соединений), цикл проверяет флаг. Создатель подключается к `127.0.0.1:5555` как обычный клиент — один путь кода для всех. Состояние сервера трогает только его поток; единственное исключение — флаг «бот на пустом месте», который экран ожидания выставляет напрямую (присваивание `bool` атомарно). Альтернатива — отдельный процесс сервера: надёжнее при падениях, но сложнее остановить и показать ошибку «порт занят».

2. **Сервер ждёт оба места.** Флаг `started`: пока не заняты оба места (подключение или бот), матч не шагает, а клиентам раз в два такта уходит снимок с `"waiting": true` — клиент показывает экран ожидания. После старта прежнее правило: матч стоит только без игроков. `--bot` у `python -m duel.server` — сразу оба места.

3. **Снимки 30 раз в секунду, протокол 2.** Сообщение `{"type": "state", "tick": N, "waiting": false, "snap": {...}, "events": [...]}` — каждые 2 такта; `events` — все события за оба такта, `tick` — номер такта сервера (растёт и между партиями). `PROTO = 2`: старые клиенты получат «другая версия протокола».

4. **Сглаживание — `duel/interp.py`, класс `Playback`.** Буфер пришедших снимков `(tick, snap, events)`. Часы показа — в тактах сервера: при первом снимке `play = tick − DELAY`, где `DELAY = 6` тактов (0,1 с = три интервала между снимками — переживает одно опоздание). Каждый кадр `play += dt·60`, с мягкой подстройкой (±10 % скорости), если отставание от `последний − DELAY` больше 2 тактов, и прыжком, если больше 30 тактов (после паузы). Если снимков дальше нет — `play` не уходит за последний: показывается последний снимок.
   - Картинка: берём снимок `a` (последний с `tick ≤ play`) и следующий `b`, `k = (play − a.tick)/(b.tick − a.tick)`. Результат — копия `a`, у магов, двойников, пуль, мобов и снарядов `x, y` сдвинуты к одноимённому (`id`) объекту из `b` на долю `k`. Объект, которого нет в `b`, стоит в своём последнем месте до смены снимка; объект, которого нет в `a`, появляется, когда `b` становится `a`. Прыжок больше 150 пикселей (зеркало, новое место) не сглаживается.
   - События снимка отдаются в тот кадр, когда `play` прошёл его `tick`, — звук и надпись совпадают с картинкой.
   Альтернатива — экстраполяция вперёд без задержки: меньше задержка, но объекты «проскакивают» и откатываются; для 2D-дуэли в локальной сети 0,1 с незаметны.

5. **Состояния приложения.** Новые `state`: `"host"` (экран ожидания создателя), `"join"` (ввод адреса). Сетевая партия — `state == "play"` при `self.net`; пока сервер ждёт второго, рисуется экран «ждём второго игрока». `self.menu_message` — строка ошибки или «связь потеряна», показывается в меню до следующего действия. Выход из сетевой партии (`leave_net`) закрывает соединение и, если игра своя, останавливает сервер.

6. **Ввод адреса — по физическим клавишам**, как и всё управление: цифры, латинские буквы по положению клавиш, точка (`.`, `,` цифровой клавиатуры), двоеточие (Shift + `;`), дефис. Так адрес набирается и в русской раскладке. Максимум 64 символа.

7. **Адрес компьютера в сети** — `net.local_addresses()`: адрес исходящего интерфейса через UDP-сокет, «подключённый» к `10.255.255.255` (пакеты при этом не уходят), плюс адреса имени компьютера; без `127.*`. Если ничего не нашлось — подсказка «узнайте адрес: hostname -I».

8. **Ошибки.** Порт занят при «Создать игру» → сообщение в меню. Ошибка подключения → на экране ввода адреса. Подключение в главном потоке с таймаутом 3 с (окно на это время не обновляется — приемлемо для локальной сети).

9. **Настройки**: `last_address` (по умолчанию `localhost`) сохраняется после удачного подключения.

## Risks / Trade-offs

- [Задержка 0,1 с между нажатием и картинкой своего мага] → в локальной сети незаметно; предсказание своего мага — этап 6.
- [Сервер в потоке делит GIL с отрисовкой создателя] → матч лёгкий (замерено: шаг и снимок — доли миллисекунды); при проблемах — отдельный процесс.
- [Гость видит сглаженную картинку, создатель — тоже через сеть] → одинаковый опыт для обоих, честнее.
- [Протокол 2 несовместим с 1] → ветка ещё не в `master`, в ходу нет старых клиентов.
