# Proposal

## Why

Это этап 1 сетевой версии (см. `docs/network-roadmap.md`). По сети клиент получит не объекты матча, а их снимок — данные. Сейчас экран берёт объекты матча напрямую, пули, мобы и маги рисуют себя сами, а всплывающие надписи берут положение мага из матча. Без снимка клиенту нечего рисовать, поэтому этот этап нужен перед сетью (этап 2: отдельный сервер `python -m duel.server` и два клиента на одном ноутбуке).

## What Changes

- **Снимок матча**: `snapshot(match)` даёт словарь только из простых значений (числа, строки, списки, словари) — время партии, волна, победитель, маги, пули, мобы, снаряды, артефакты, пачки патронов, стены, двойники. У каждого объекта номер `id`. Снимок проходит через JSON без изменений.
- **Экран рисует только по снимку**: поле, статус наверху, таймер волн, надпись о победе. Отрисовка уезжает из сущностей (`entities.py`) в модуль отрисовки; цвет и спрайт выводятся из `blue` / `red`.
- **Надписи по снимку**: приложение показывает всплывающие надписи по событиям матча и положению магов из снимка, а не из объектов матча.
- **Хотсит через снимки**: после каждого такта приложение берёт снимок и рисует по нему — так снимок проверяется в обычной игре.
- Поведение игры для игрока **не меняется**: та же картинка, правила, звуки и надписи.

## Impact

- Код: новый `duel/snapshot.py` (снимок матча); новый `duel/render.py` (отрисовка объектов поля по снимку); методы `draw` и `draw_effects` убираются из `entities.py` (сущности больше не импортируют отрисовку); `screens.py` и `game.py` читают снимок.
- Тесты: снимок → JSON → снимок равен исходному; картинка по снимку и по снимку после JSON совпадает пиксель в пиксель; в снимке есть всё, что нужно экрану; матч и снимок работают без pygame-окна.
- Документация: `RUNBOOK.md` (снимок, где рисовать), `docs/network-roadmap.md` (этап 1 выполнен), `openspec/config.yaml`.
- Вне этого изменения (этап 2): сервер, сеть, флаги `--connect`, `--windowed`, геймпад в фоновом окне.
