# Proposal

## Why

Это первая часть этапа 2 сетевой версии (см. `docs/network-roadmap.md`): хочется запустить сервер и посмотреть, как игра выглядит по сети, — на одном ноутбуке или на двух компьютерах в одной сети. Этапы 0 и 1 подготовили почву: матч работает без окна и без pygame, экран рисует только по снимку. Прототип уже собран в ветке `feature/network`; это изменение описывает его поведение, закрывает тестами и документацией.

## What Changes

- **Сервер без окна**: `python -m duel.server` ведёт матч и ждёт игроков на порту (по умолчанию 5555). Первый подключившийся — синий, второй — красный, третий получает отказ «мест нет». С `--bot` пустое место занимает бот. Матч идёт, пока подключён хоть один игрок.
- **Сетевой клиент**: `python main.py --connect АДРЕС [--windowed] [--pad N]` — подключается, рисует матч по снимкам с сервера, играет звуки и показывает надписи по событиям. Обе раскладки клавиатуры и свой геймпад управляют своим магом. Esc закрывает клиент, R после победы просит у сервера новую партию.
- **Окно вместо полного экрана** (`--windowed`) и **геймпад без фокуса окна** у клиента — два клиента на одном компьютере, каждый со своим геймпадом.
- **Протокол**: сообщения JSON по TCP, по одному в строке; первое сообщение сервера — приветствие с версией протокола, ролью (`player`) и цветом игрока. Клиент с другой версией протокола не подключается молча, а сообщает об ошибке.
- Хотсит (`python main.py`) не меняется.

Вне этого изменения (следующие части этапа 2 и этап 3): пункты меню «Создать игру» / «Подключиться», реже снимки и плавная анимация между ними, лобби и «готов», переподключение, поиск игр в сети, зрители.

## Capabilities

### New Capabilities

- `network-play`: игра по сети — сервер без окна, подключение клиентов, роли, бот на пустом месте, версия протокола, отключение, клиент в окне и с геймпадом без фокуса.

### Modified Capabilities

## Impact

- Код: `duel/server.py`, `duel/net.py`, `duel/bot.py` (бот, общий для сервера и отпечатка партии); `duel/game.py` — режим сетевого клиента; `main.py` — аргументы запуска; `tools/fingerprint.py` берёт бота из `duel/bot.py`.
- Тесты: протокол (строки JSON, адрес), сервер и клиенты через настоящие сокеты в одном процессе — роли, команды доходят до матча, снимки и события приходят, бот, отказ при занятых местах, другая версия протокола, отключение игрока, рестарт после победы.
- Документация: `RUNBOOK.md` (как запустить сервер и клиентов), `docs/network-roadmap.md`.
- Ветка: `feature/network`; в `master` вливается, когда этап 2 станет удобен для игры.
