# Design

## Context

После этапов 0 и 1 матч (`duel/match.py`) работает без окна и без pygame, шагает по командам и отдаёт события; снимок (`duel/snapshot.py`) — простые данные, экран рисует только по нему. В ветке `feature/network` собран прототип: `duel/server.py`, `duel/net.py`, режим клиента в `Game`, аргументы `main.py`, бот вынесен в `duel/bot.py`. Он проверен вручную (сервер с ботом + клиент без окна), но не покрыт тестами, ошибки подключения падают трассировкой, документации нет.

## Goals / Non-Goals

**Goals:**
- Сервер и клиент по описанию `network-play`, проверенные автотестами через настоящие сокеты.
- Понятные сообщения при ошибках подключения (нет сервера, мест нет, другая версия).
- Инструкция запуска в `RUNBOOK.md`.

**Non-Goals:**
- Пункты меню «Создать игру» / «Подключиться», имя игрока, последний адрес в настройках.
- Реже снимки, сжатие, плавная анимация между снимками, предсказание своего мага.
- Лобби, «готов», переподключение, поиск игр, зрители, портал.

## Decisions

1. **Транспорт — TCP, сообщения — JSON по одному в строке.** Строка проще длины-префикса и легко читается глазами (`nc localhost 5555`). JSON не содержит переводов строк, поэтому разделитель надёжен. Альтернатива — длина + тело (как в плане): понадобится, если появятся бинарные данные; переход — внутри `duel/net.py`.

2. **Неблокирующие сокеты и `select` на сервере, один поток.** Сервер ждёт до следующего такта или до прихода данных, принимает подключения, читает команды, делает такты. Нет гонок и блокировок. Отправка копится в буфере соединения; клиент, у которого накопилось больше 1 МБ (не читает — это около 7 секунд снимков), отключается; буфер дописывается без копирования, чтобы медленный клиент не тормозил сервер.

3. **Такты сервера 60 Гц по `time.monotonic`, без догонялок после паузы больше 0,25 с.** Снимок и события рассылаются каждый такт: в локальной сети и на одном компьютере 60 снимков в секунду по несколько килобайт — не проблема, а плавность бесплатна. Реже снимки + интерполяция — следующее изменение.

4. **Команды клиента каждый такт.** Направление держится на сервере до следующей команды; нажатия (выстрел, удар, ячейка) складываются до ближайшего такта и применяются один раз. Значения проверяются: направление обрезается до −1…1, ячейка — только 0–3.

5. **Приветствие: `{"type": "hello", "proto": 1, "role": "player", "you": "blue"}`.** Клиент ждёт его до 5 секунд; другая версия → `ConnectionError` с понятным текстом. Роль заложена под зрителей (этап 4). Отказ — `{"type": "full"}`.

6. **Клиент — тот же `Game` с `net`.** Вместо шагов локального матча — `net_frame`: команды своего мага, приём снимков и событий; события превращаются в звук и надписи тем же `handle_events`. Обе раскладки и свой геймпад (`--pad`) — для своего мага. Локальный матч клиента не шагает.

7. **Геймпад без фокуса — подсказка SDL `SDL_JOYSTICK_ALLOW_BACKGROUND_EVENTS=1`**, выставляется до инициализации pygame только у сетевого клиента. В хотсите не нужна.

8. **Ошибки запуска клиента.** `main.py` ловит `ConnectionError` и `OSError` при подключении и печатает одну строку («не удалось подключиться к localhost:5555: …») с кодом выхода 1, без трассировки.

9. **Тесты через настоящие сокеты в одном процессе.** Сервер слушает порт 0 (свободный, выдаёт система); тест шагает сервер вручную (`accept`, `read`, `tick`) — без потоков и без ожидания реального времени. Клиенты — `Conn` или `Game` с `net`.

## Risks / Trade-offs

- [60 снимков в секунду по сети медленнее локальной — подтормаживание] → в локальной сети хватает; реже снимки с интерполяцией — следующее изменение.
- [Без лобби партия начинается сразу с первым игроком] → для «посмотреть» это удобно; лобби — этап 3.
- [Подсказка SDL для фона может не сработать на какой-то платформе] → проверено на Linux; в худшем случае один клиент управляется клавиатурой в фокусе.
- [Клиент доверяет серверу] → для игры с друзьями приемлемо; сервер проверяет команды клиентов.

## Migration Plan

В ветке `feature/network`; хотсит не меняется. В `master` — когда этап 2 станет удобен для игры (меню и плавность). Откат — не вливать ветку.
