# Design

## Context

Экран «Подключиться» (`state == "join"` в `duel/game.py`, `draw_join` в `duel/screens.py`) — одно поле адреса. Сервер (`duel/server.py`) — однопоточный цикл на `select`: слушает TCP, шагает матч, рассылает снимки; из меню запускается в фоновом потоке (`start_in_thread`). Адреса компьютера уже умеет находить `net.local_addresses()`. Типичная сеть — раздача Wi-Fi с телефона (Android: `192.168.43.0/24`, iPhone: `172.20.10.0/28`) или домашний роутер.

## Goals / Non-Goals

**Goals:**
- Подключение выбором из списка, без знания адреса.
- Ничего не ломается, если поиск в сети не проходит: ручной ввод остаётся.

**Non-Goals:**
- Поиск за пределами своей сети (интернет, виртуальные сети) — только ручной адрес.
- Имя игрока, лобби, «готов», переподключение (дальше в этапе 3).

## Decisions

1. **Вопрос клиента — ответ сервера, а не постоянные объявления.** Экран «Подключиться» раз в секунду шлёт широковещательный UDP-пакет `{"type": "who", "game": "duel"}` на порт 5556; каждый сервер отвечает тому, кто спросил (обычный UDP на адрес отправителя): `{"type": "here", "game": "duel", "proto": 2, "port": 5555, "name": "papa-laptop", "free": 1}`. Сеть не засоряется, пока никто не ищет, а ответ приходит с правильного интерфейса сам. Альтернатива — сервер объявляет себя раз в секунду всем: проще клиенту, но сервер должен угадывать широковещательный адрес каждой сети.

2. **Куда слать вопрос.** На `255.255.255.255` (вся своя сеть) и дополнительно на широковещательные адреса сетей компьютера, вычисленные как `/24` из `local_addresses()` (на случай, если система шлёт `255.255.255.255` только через один интерфейс). Неверная догадка о маске ничего не ломает: лишний пакет просто никто не получит.

3. **Сервер слушает UDP 5556 в том же цикле `select`.** Сокет с `SO_REUSEADDR` (и `SO_REUSEPORT`, где есть), привязан к `0.0.0.0:5556`. Не удалось привязать — сервер пишет в журнал и работает без поиска. Ответ на каждый вопрос; битые и чужие пакеты (`game != "duel"`, не JSON) молча игнорируются; размер пакета ограничен 1 КБ.

4. **Клиент поиска — `discovery.Finder`**: неблокирующий UDP-сокет, `poll()` раз в кадр на экране «Подключиться»: раз в секунду шлёт вопрос, собирает ответы, хранит `{(адрес, порт): (ответ, время)}`, отдаёт список свежее 3 секунд, отсортированный по имени. Закрывается при уходе с экрана.

5. **Состояние в ответе**: `free` — свободные места (2 − подключённые, с ботом — 0 после начала партии), `proto` — версия. Экран пишет «ждёт второго игрока» (`free > 0`), «мест нет» (`free == 0`), «другая версия игры» (`proto` не наш); к таким двум подключиться всё равно можно попробовать — ошибка покажется как обычно.

6. **Экран «Подключиться»** — список строк: найденные игры, затем строка ручного ввода. `join_pick` — адрес выбранной игры (или `None` — строка ввода); стрелки ↑/↓ и крестовина двигают выбор (W/S здесь — буквы адреса); печатные клавиши адреса — переход на строку ввода и набор; Enter/✕ — подключиться к выбранному. Пока список пуст, выбрана строка ввода (как раньше). Имя компьютера — `socket.gethostname()`.

7. **Брандмауэр.** На Linux с включённым `ufw` нужны `5555/tcp` и `5556/udp`; на Windows при первом запуске система спросит разрешение — надо разрешить для частных сетей. Это пишется в RUNBOOK и в подсказке «ничего не найдено».

## Risks / Trade-offs

- [Раздача с телефона изолирует устройства или режет широковещательные пакеты] → ручной ввод адреса остаётся; подсказка на экране.
- [Догадка `/24` неверна (iPhone `/28`)] → основной путь — `255.255.255.255`; догадка лишь дополняет.
- [Имя компьютера видно всем в сети] → это локальная сеть дома; имя игрока — позже, в настройках.

## Migration Plan

В `master` (сетевую ветку не используем, пока нет параллельных игровых изменений). Протокол игры не меняется; старые клиенты просто не ищут. Откат — `git revert`.
